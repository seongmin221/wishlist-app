# 헤드라인 둘째 줄 색 계산

> 상태: **확정** · 최종 갱신: 2026-09-25 · 관련: [시각 디자인 방향](../../history/product-planning/mvp/decisions/visual-direction.md)

## 목적

화면 헤드라인은 두 줄로 쓴다. 첫 줄은 상태, 둘째 줄은 회색 안내다. 둘째 줄을 고정 회색으로 쓰면 뒤에 목적 색 같은 다른 색 면이 깔렸을 때 색감이 어긋나고 대비가 떨어진다. 이 문서는 둘째 줄 색을 뒤 배경에 맞춰 정하는 규칙과 계산 방법을 정한다.

## 규칙

| 뒤 배경 | 둘째 줄 색 | 예 |
| --- | --- | --- |
| 기본 바탕 `#F7F7F3` (또는 흰색) | 글자색 `#111111`을 50% 불투명도로 겹친 색 | 홈, 카테고리, 목적 헤드라인 |
| 목적 색 등 다른 색 면 | 그 면의 색으로 **직접 계산한 불투명 색** | 아카이브 기록 상세의 목적 색 머리띠 |

기본 바탕에서는 투명도만 쓰면 된다. 다른 색 면 위에서는 투명도로 겹치지 않고 아래 공식으로 불투명 색을 만든다. 면의 색이 목적마다 바뀌어도 둘째 줄이 그 색의 어두운 톤으로 따라가서 어울리고, 대비도 더 확보된다.

## 계산

sRGB 채널별 선형 혼합으로 계산한다.

```text
secondary = surface × 0.45 + ink × 0.55     (ink = #111111, 채널마다 반올림)
```

- `surface`: 둘째 줄 바로 뒤에 깔린 면의 색(투명도가 없는 최종 색)
- 비율 `0.45`는 면 색의 비중이다. 값을 낮출수록 둘째 줄이 진해진다.

기본 바탕의 `ink 50%`도 같은 식으로 풀면 `secondary = surface × 0.5 + ink × 0.5`이다. 두 규칙은 면 색 비중만 다르다.

## 계산 결과와 대비

대비는 WCAG 상대 휘도로 계산했다. 헤드라인 둘째 줄은 22px 굵은 글자라 큰 글자 기준(3:1)을 적용한다.

| 면 색 | 용도 | 기본 규칙(50%) | 대비 | 계산 규칙(45% 면) | 대비 |
| --- | --- | --- | --- | --- | --- |
| `#F7F7F3` | 기본 바탕 | `#848482` | 3.49 | — | — |
| `#FFFFFF` | 흰 면 | `#888888` | 3.54 | — | — |
| `#CFE3F0` | 목적 색(하늘) | `#707A80` | 3.32 | `#667075` | 3.84 |
| `#DCD6F0` | 목적 색(라벤더) | `#767480` | 3.26 | `#6C6A75` | 3.77 |
| `#F3D9C9` | 목적 색(살구) | `#82756D` | 3.30 | `#776B64` | 3.83 |

이전 고정 회색 `#A5A59E`는 기본 바탕에서도 대비가 2.31로 큰 글자 기준에 못 미쳐 이 규칙으로 바꿨다.

## 구현

- 목적 색 목록은 앱이 정한 고정 팔레트이므로, 각 색의 둘째 줄 색을 미리 계산해 색 토큰으로 두는 것을 우선한다(`purposeSurface` ↔ `purposeSecondaryText`).
- 팔레트 밖의 색 면이 생기면 같은 공식을 쓰는 순수 함수로 계산한다. UI 프레임워크에 의존하지 않으므로 KMP 공통 계층에 둘 수 있다.

```kotlin
// KMP 공통: ARGB Int -> ARGB Int
import kotlin.math.roundToInt

fun secondaryTextOn(surface: Int, ink: Int = 0xFF111111.toInt(), surfaceWeight: Double = 0.45): Int {
    fun ch(c: Int, shift: Int) = (c shr shift) and 0xFF
    fun mix(shift: Int) = (ch(surface, shift) * surfaceWeight + ch(ink, shift) * (1 - surfaceWeight)).roundToInt()
    return (0xFF shl 24) or (mix(16) shl 16) or (mix(8) shl 8) or mix(0)
}
```

- iOS(SwiftUI)와 Android(Compose)는 기본 바탕에서는 `ink.opacity(0.5)` / `ink.copy(alpha = 0.5f)`를 쓰고, 색 면 위에서는 위 함수 결과나 미리 계산한 토큰을 불투명 색으로 쓴다.
- 계산 결과가 큰 글자 기준 3:1에 못 미치면 `surfaceWeight`를 0.05씩 낮춰 다시 계산한다. 현재 팔레트에서는 모두 3:1 이상이다.

## 검증

- 팔레트의 모든 목적 색에 대해 계산 결과가 위 표와 같은지 단위 테스트한다.
- 각 결과의 대비가 3:1 이상인지 확인한다.
