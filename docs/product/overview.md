# 제품 개요

> 상태: **제안** · 최종 갱신: 2026-09-10

## 제품 목적

브라우저나 지원 앱에서 발견한 상품 URL을 빠르게 보관하고, 보강된 정보를 개인 위시리스트에서 비교·정리해 구매 결정을 기록하는 native 모바일 앱이다.

## 핵심 원칙

- 저장 의도는 로그인·네트워크·분석 결과보다 먼저 보존한다.
- 위시리스트는 URL 저장소가 아니라 같은 상품 유형의 구매 후보를 비교하는 도구다.
- AI는 taxonomy 안에서 분류와 기존 목적 연결을 보조하며, 사용자의 선택을 대체하지 않는다.
- 비교를 끝낸 기록은 활성 목록과 분리해 안전하게 보존한다.

## MVP 범위

### 포함

- 사용자별 위시리스트, 최초 로그인 유도와 건너뛰기
- URL 공유, 정규화·중복 후보 탐지, 비동기 metadata 추출과 가능한 제목·이미지·판매처·가격·통화·brand 보강
- 출시 기준 taxonomy의 AI 분류와 사용자 카테고리 수정
- 목적별 비교 묶음, 기존 목적에 대한 AI 연결, 연결 결과 검토·수정
- 처리 상태·카테고리별 목록, 누락 정보의 직접 보완과 사진 보관함 이미지 선택, 항목 삭제
- 목적 비교 종료 시 선택적 구매 상품 지정, 후보 일괄 아카이브와 기록 제목 수정

### 제외

- 가격 변동, 품절·재입고 알림과 주기적 상품 재수집
- 전문 검색, 유사 상품, 개인화 추천
- 자체 ML 모델 학습·호스팅, GPU 운영, embedding/vector DB/RAG
- 모든 쇼핑몰의 JS 렌더링·bot protection 우회와 공유용 웹페이지

## 전체 사용자 여정

1. 사용자는 [상품 저장](save-a-product.md)에서 URL을 공유하고 분석 결과를 받거나 복구한다.
2. [구매 후보 정리](organize-candidates.md)에서 카테고리·목적·중복 후보를 사용자의 의도대로 정리한다.
3. [상품 확인과 편집](inspect-and-edit-a-product.md)에서 목록을 보고 정보를 보완·수정하거나 원본 링크를 확인한다.
4. [구매 결정 종료](finish-a-purchase-decision.md)에서 비교를 끝내고 구매 선택과 아카이브 기록을 관리한다.

공통 상태 용어는 [상품 상태 용어](references/item-states.md), 출시 기준 분류는 [상품 taxonomy](references/product-taxonomy.md)를 따른다.

## 향후 범위

MVP 제외 항목의 구체적인 기획은 시작하지 않았다. 실제 제품 요구가 생길 때 이 문서에서 범위를 정한 뒤 별도 현재 product 문서로 분리한다.

| 단계 | 후보 기능 | 선행 조건 |
| --- | --- | --- |
| V1 | 검색 | MVP의 목적별 비교 묶음 사용 경험 검증 |
| V2 | 유사 상품, 취향 기반 추천, semantic search, 위시리스트 공유 웹페이지 | 충분한 상품·사용자 행동 데이터, embedding 평가, 공개 범위·권한 정책 |
| V2 이후 | 가격·재고 알림, 주기적 재수집, 선호 통화 기준 참고 환산 | 신뢰할 수 있는 상품 식별자, 수집·알림·환율 정책 |

출시 단계가 정해지지 않은 후보는 이미지 URL 입력, 웹 이미지 검색, 명시적 기존 상품 일괄 재검토, 최근 저장순 외 대체 정렬 기준이다.

확장된 JS 렌더링 지원과 AI 인프라 확장도 별도 요구와 기술 설계가 생길 때 검토한다.

## 제품 수준 미결정 사항

현재 MVP의 흐름 간 제품 결정은 추가로 열려 있지 않다. 공급자 선택, 처리 완료 전달 방식, Playwright 적용 범위 등 구현 선택은 [서버 구조](../architecture/server/overview.md)의 기술 미결정 사항으로 관리한다.
