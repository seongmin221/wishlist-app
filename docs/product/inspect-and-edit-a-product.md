# 상품 확인과 편집

> 상태: **제안** · 최종 갱신: 2026-09-10 · 관련 흐름: 홈·일반 목록 확인, 정보 보완·편집, 원본 링크 탐색과 활성 상품 삭제

## 사용자 목표

저장한 상품에서 지금 필요한 조치를 한눈에 확인하고, 정보가 부족하면 최소 정보만 보완하며, 언제든 원본 페이지를 다시 열어 확인·수정하거나 활성 목록에서 제거한다.

## 제품 원칙

- 홈의 조치 필요 영역과 일반 카테고리 목록 포함 여부는 별도로 판단한다. 하나의 상품은 홈 조치 영역 한 곳에만 보인다.
- 일반 목록에 쓸 최소 정보는 제품명과 카테고리다. 추출 상태나 분류·목적 검토가 그 사용을 막지 않는다.
- 직접 보완과 일반 편집은 하나의 화면에서 하며, 직접 보완을 끝낸 정보는 사용자의 선택으로 계속 사용한다.

## 범위

이 문서는 홈·일반 목록의 표시, 정보 보완과 상품 정보 편집 화면의 진입·표현, 원본 링크 웹뷰, 활성 상품 삭제를 소유한다. 공통 상태 용어는 [상품 상태 용어](references/item-states.md)를 따른다.

URL 수신·분석·재시도와 분석 중 삭제는 [상품 저장](save-a-product.md)이 소유한다. 카테고리와 목적의 연결·변경·해제, `분류·목적 확인`의 검토 결과는 [구매 후보 정리](organize-candidates.md)가 소유한다. 이 편집 화면은 그 행동의 진입점과 현재 연결의 표시만 제공하며, 결과 규칙을 다시 정의하지 않는다. 아카이브와 아카이브 기록 삭제는 후속 `finish-a-purchase-decision.md`에서 다룬다.

## 사용자 흐름

### 1. 홈의 조치 필요 영역

앱의 기본 진입 화면은 카테고리별 구매 후보를 살펴보기 전에 조치가 필요한 항목을 요약한다. `분석 대기`, `분류 중`, `정보 보완 필요`, `카테고리 미지정`, `분류·목적 확인` 중 항목이 있는 영역만 표시한다.

하나의 상품은 다음 우선순위로 **하나의** 조치 필요 영역에만 표시한다.

1. `분석 대기` — 서버 전송 전
2. `분류 중` — 서버 분석 중
3. `정보 보완 필요` — 제품명이 없거나 추출 결과에서 카테고리를 정하지 못함
4. `카테고리 미지정` — 사용자 전용 카테고리 삭제 뒤 재지정을 건너뜀
5. `분류·목적 확인` — 필수 정보는 있지만 자동 분류 결과가 미확정

어느 조건에도 해당하지 않는 상품은 홈 조치 필요 영역에 표시하지 않는다. `카테고리 미지정`은 정보 누락이나 추출 실패가 아니므로 그 상태만으로 `정보 보완 필요`에 표시하지 않는다. `분류·목적 확인`의 확인·보류·목적 연결과 중복 후보 정리 결과는 [구매 후보 정리](organize-candidates.md)를 따른다.

### 2. 일반 목록과 가격 표시

카테고리는 구매 후보를 비교하는 일반 목록의 기본 그룹 기준이고, 각 항목의 저장 시점도 함께 보관한다. 같은 카테고리의 활성 항목은 최근 저장순으로 표시하며, MVP에서는 다른 정렬 기준을 제공하지 않는다.

제품명과 카테고리가 있으면 `분류·목적 확인` 전에도 일반 카테고리 목록에 표시한다. 정보가 완성된 항목은 일반 상품 카드로 표시하고 내부 `READY` 상태는 별도 화면 상태로 강조하지 않는다. `PARTIAL`도 이 두 필수 정보가 있으면 일반 목록에 표시한다.

가격은 비교를 위한 참고 정보다. 추출된 가격에는 원래 금액·통화와 마지막 확인 시점을 함께 표시하며, 실시간 가격임을 보장하지 않는다. 통화는 ISO 4217 코드와 함께 보관하고 항목마다 원래 통화로 표시한다. MVP는 서로 다른 통화를 환율로 환산하지 않는다.

## 상태와 전환

### 정보 보완 필요와 직접 보완 완료

일반 목록의 필수 정보는 **제품명, 카테고리**다. 대표 이미지, 가격, 통화, 판매처, 브랜드, 목적은 선택 정보다. `PARTIAL` 또는 `FAILED` 결과에서 제품명 또는 카테고리가 없으면 `정보 보완 필요`에 표시하고, 실패·누락 사실, 원본 링크 열기, 제품명·대표 이미지·카테고리 직접 입력을 제공한다.

사용자가 제품명과 카테고리를 모두 입력해 저장하면 추출 상태와 관계없이 `정보 보완 필요`에서 빠져 해당 카테고리의 일반 목록으로 이동한다. 대표 이미지가 없으면 기본 이미지를 표시하고 나중에 추가할 수 있다. 직접 보완을 저장한 항목은 이후 서버 재분석 대상에서 제외하고 직접 입력한 정보로 계속 사용한다. 원래 서버 추출 실패 기록은 내부 진단 정보로 유지한다.

`PROCESSING` 항목은 원본 링크, 로딩 인디케이터, `상품 정보 추출 중` 문구를 표시한다. 이 상태에서는 수정·재추출이 아니라 삭제만 가능하며, 처리 중 삭제와 늦게 도착한 결과의 처리는 [상품 저장](save-a-product.md)을 따른다.

## 상품 정보 편집

직접 보완과 추출 완료 뒤 수정은 같은 상품 정보 편집 화면에서 수행한다. 이 화면은 제품명, 대표 이미지, 카테고리를 한 번에 입력·수정하고 원본 링크를 여는 제어를 제공한다. 카테고리는 AI 결과와 관계없이 언제든 변경할 수 있다.

현재 목적 연결도 이 화면에서 표시하고 기존 목적을 선택·변경하거나 해제하는 진입점을 제공한다. 목적 연결의 허용 조건, 변경·해제 결과, 목적 미지정 처리와 AI 재판단은 [구매 후보 정리](organize-candidates.md)를 따른다.

대표 이미지는 MVP에서 사진 보관함에서 선택해 추가한다. 이미지 URL 입력과 웹 이미지 검색은 MVP 이후 범위다.

## 원본 링크 웹뷰

모든 상품 링크는 `PROCESSING`, `READY`, `PARTIAL`, `FAILED`를 포함한 처리 상태와 무관하게 앱 내 웹뷰로 연다. iOS와 Android 모두 앱 navigation 화면으로 열며, 닫으면 열기 전 앱 화면과 상태로 돌아간다.

- 닫기는 좌측 상단에 둔다.
- 뒤로 가기와 앞으로 가기는 좌측 하단에 둔다. 뒤로 가기는 웹페이지 방문 기록을 먼저 이동하고, 이전 페이지가 없으면 웹뷰를 닫는다.
- 새로고침과 공유는 우측 하단에 둔다. 공유 메뉴에는 외부 브라우저로 열기가 있다.
- 웹페이지가 새 창을 요청하면 별도 창을 만들지 않고 현재 웹뷰에서 열어, 뒤로 가기로 원래 페이지에 돌아올 수 있게 한다.
- 사용자가 직접 누른 링크가 결제 앱 등 외부 앱을 요청하면 실행을 허용한다. 사용자 동작 없이 외부 앱을 열려고 하면 확인을 받는다.
- 쇼핑몰 로그인이 유지되도록 쿠키를 방문 간 유지하고, 앱 설정에서 웹뷰 데이터를 삭제할 수 있게 한다.

외부 앱에서 돌아오면 열려 있던 웹뷰와 방문 기록을 유지하고 강제로 새로고침하지 않는다. OS가 앱 프로세스를 종료했을 때는 최소한 원래 상품 URL과 앱 navigation 위치를 복원할 수 있게 설계한다. 결제 완료를 자동 감지해 구매 확정이나 아카이브를 수행하지 않는다.

## 예외와 복구

추출 실패·누락은 일반 목록 사용을 포기해야 하는 상태가 아니라 직접 보완으로 끝낼 수 있는 상태다. 직접 보완 전 분석 실패의 재시도는 [상품 저장](save-a-product.md), 카테고리 재지정을 건너뛴 뒤의 분류 규칙은 [구매 후보 정리](organize-candidates.md)를 따른다.

## 활성 상품 삭제

활성 상품 삭제는 아카이브와 별도의 동작이며 실행 취소를 제공하지 않는다. 삭제 확인창에는 연결된 목적 이름과 그 목적의 비교 후보에서 상품이 제거된다는 사실을 표시한다. `?` 도움말에서는 삭제 뒤 목적에 남는 상품 수, 마지막 상품을 지워도 빈 목적이 유지되는 점, 기존 아카이브 스냅샷에는 영향이 없는 점을 설명한다.

목적 미지정 상품을 삭제할 때는 목적 영향 안내를 표시하지 않는다. 상품 삭제는 목적 자체나 다른 상품을 바꾸지 않는다. 중복 후보 검토에서 기존 상품을 삭제할 때도 같은 목적 영향 정보를 제공하며, 후보 선택 규칙은 [구매 후보 정리](organize-candidates.md)를 따른다.

분석 중인 항목의 삭제와 늦은 결과 무시는 [상품 저장](save-a-product.md)을 따르고, 아카이브 기록의 묶음 삭제와 실행 취소 규칙은 후속 `finish-a-purchase-decision.md`가 소유한다.

## 제품 규칙

- 홈 조치 영역의 우선순위와 일반 목록 포함은 별도 판단이며, 분류·목적 검토가 일반 목록 사용을 막지 않는다.
- 상품 정보는 사용자의 `WishlistItem`에 표시되는 값으로 편집하며, 공용 캐시와 다른 사용자의 항목을 갱신하지 않는 경계는 [상품 저장](save-a-product.md)을 따른다.
- 가격·통화와 마지막 확인 시점은 참고용 표시이며, 가격 자동 갱신·가격 알림·환율 환산은 MVP 범위에 포함하지 않는다.

## 미결정 사항

- 홈 요약 화면의 상세 배치와 시각 디자인, `PROCESSING` 카드의 구체적 표현, 정보 완성 카드의 상세 구성에는 원본 스펙의 제안 근거가 남아 있다.
- 카테고리 목록의 최근 저장순 외 정렬, 가격·통화·마지막 확인 시점의 표시 형식, 편집 화면의 구체적 레이아웃은 아직 결정하지 않았다.
