# 구매 후보 정리

> 상태: **제안** · 최종 갱신: 2026-09-10 · 관련 흐름: 저장된 상품의 분류, 목적 연결, 검토와 중복 정리

## 사용자 목표

저장한 상품이 무엇인지 분류하고 무엇을 위해 비교하는지 묶은 뒤, 자동 제안과 중복 후보를 사용자의 의도대로 정리한다.

## 제품 원칙

- 카테고리는 상품이 **무엇인지**를 나타내는 분류이고, 목적은 사용자가 상품을 **왜 비교하는지**를 나타내는 선택적 맥락이다. 예를 들어 `디지털 > 헤드폰`은 카테고리이고 `출퇴근용 노이즈 캔슬링 헤드폰`은 목적이다.
- AI는 공용 taxonomy나 새 목적을 만들지 않는다. 자동 결과는 근거가 있을 때만 제안하며, 사용자의 확정·변경·해제가 우선한다.
- 중복 가능성은 저장을 막는 근거가 아니라 사용자가 비교해 정리할 후보를 만드는 근거다.

## 범위

이 문서는 공용·사용자 전용 카테고리, 목적 생성·연결·삭제, AI 분류·목적 연결, `분류·목적 확인`, 중복 후보 비교와 정리를 소유한다. 공용 용어는 [상품 상태 용어](references/item-states.md), 출시 기준 분류 목록은 [상품 taxonomy](references/product-taxonomy.md)를 따른다.

URL 수신·처리와 중복 후보 탐지는 [상품 저장](save-a-product.md)이 소유한다. 일반 목록의 최소 정보·표시 조건과 상품 편집 화면의 진입·표현은 [상품 확인과 편집의 상품 정보 편집](inspect-and-edit-a-product.md#상품-정보-편집)이 소유하되, 그 화면에서 하는 목적 연결·변경·해제의 규칙과 결과는 이 문서를 따른다. 목적 종료 뒤 아카이브는 [구매 결정 종료의 구매 상품 지정과 비교 종료](finish-a-purchase-decision.md#1-구매-상품-지정과-비교-종료)가 소유한다.

## 사용자 흐름

### 1. 카테고리 선택과 사용자 전용 세부 카테고리

공용 taxonomy는 출시 기준의 공통 분류다. 사용자는 공용 카테고리의 이름을 바꾸거나 삭제할 수 없고, AI도 공용 taxonomy에 새 카테고리를 만들지 않는다. 공용 목록에 없는 상품은 사용자가 선택한 공용 상위 카테고리 아래에 자신의 사용자 전용 **세부** 카테고리를 만들 수 있다. 이는 공용 taxonomy를 변경하는 일이 아니다.

사용자 전용 카테고리는 이름이 필수이고 설명과 포함 예시는 선택이다. 출시 시 사용자당 최대 **20개**까지 만들 수 있으며, 실제로 20개를 넘는 수요가 확인되면 한도 상향을 검토한다. 이름은 최대 **40자**, 설명은 최대 **200자**, 포함 예시는 최대 **5개**, 각 예시는 최대 **60자**다.

중복 판단을 위해 같은 상위 카테고리 안에서는 이름의 앞뒤·연속 공백을 정리한다. 정리한 이름이 같으면 만들 수 없지만, 서로 다른 상위 카테고리에서는 같은 이름을 허용한다. 이 정리는 중복 판단에만 쓰며 사용자가 입력한 텍스트를 자동으로 수정하거나 카테고리 적합성을 이유로 수정·재입력하게 하지 않는다.

다음 요청은 생성 자체를 거부한다.

- 이름이 비어 있음
- 이름·설명·예시의 길이 또는 개수 제한 초과
- 표시할 수 없는 제어문자 포함
- 짧은 시간에 과도한 생성 요청 반복

명령문 형태의 prompt injection, URL·코드·스크립트 중심 입력, AI 입력에 부적절한 유해 텍스트는 생성 거부 사유가 아니다. 해당 카테고리는 입력한 그대로 개인 목록에 보존하고 사용자가 상품에 직접 지정할 수 있다. 다만 AI 자동 분류 후보에서만 내부적으로 제외하며, 사용자 텍스트를 자동 수정하지 않고 AI 후보 제외 여부도 MVP 화면에 따로 보이지 않는다.

### 2. 사용자 전용 카테고리 변경과 삭제

사용자 전용 세부 카테고리만 이름을 변경하거나 삭제할 수 있다. 이름을 변경하면 연결된 모든 활성 상품에 새 이름을 즉시 반영한다.

연결된 활성 상품이 있는 사용자 전용 카테고리를 삭제할 때 확인창은 영향받는 상품 수를 표시하고, 드롭다운으로 목록을 펼쳐 볼 수 있게 한다. 삭제 뒤에는 각 상품을 연속해서 다른 카테고리로 재지정하거나 재지정을 건너뛸 수 있다. 건너뛴 상품은 정보가 부족한 것이 아니라 `카테고리 미지정`으로 남으며, 이 조치 영역의 정확한 노출 조건은 [상품 확인과 편집의 홈의 조치 필요 영역](inspect-and-edit-a-product.md#1-홈의-조치-필요-영역)이 소유한다.

카테고리 변경·삭제가 아카이브 기록에 미치는 영향과 스냅샷 보존은 [구매 결정 종료의 아카이브 기록과 스냅샷](finish-a-purchase-decision.md#3-아카이브-기록과-스냅샷)을 따른다.

### 3. 목적 만들기와 연결

목적은 사용자 전용 비교 묶음이다. 사용자는 목적 탭의 `목적 추가`에서 목적을 만들며 이름은 필수, 설명과 아이콘은 선택이다. 새 목적은 항목 없이 만들 수 있고, 상품 목록에서 포함할 항목을 선택할 수 있다. 빈 목적은 자동으로 삭제하지 않는다.

활성 항목은 원칙적으로 카테고리 하나와 목적 0~1개를 가진다. 목적은 필수가 아니므로 연결하지 않거나 `목적 미지정`으로 둘 수 있다. 외부 링크로 새 항목이 추가된 뒤 `분류·목적 확인`에서 기존 목적을 선택하거나 새 목적을 만들어 즉시 연결할 수 있다. 상품 정보 편집 화면에서도 사용자는 기존 목적을 선택·변경하거나 연결을 해제할 수 있으며, 이 목적 연결의 규칙과 결과는 이 문서가 소유한다.

### 4. 목적 삭제

연결된 활성 상품이 있는 목적을 삭제하면 목적만 삭제한다. 연결된 상품을 삭제하거나 아카이브하지 않고 모두 `목적 미지정`으로 전환한다. 이는 사용자가 영향을 확인하고 명시적으로 확정한 결과이므로 상품은 `확정된 목적 미지정` 상태가 되며 `분류·목적 확인` 대상으로 다시 올리지 않는다.

삭제 확인창에는 `목적 미지정`으로 전환될 상품 수를 표시하고, 드롭다운으로 영향받는 상품 목록을 확인할 수 있게 한다. 삭제 직후 실행 취소는 제공하지 않는다. 활성 목적 삭제가 아카이브 기록에 미치는 영향은 [구매 결정 종료의 아카이브 기록과 스냅샷](finish-a-purchase-decision.md#3-아카이브-기록과-스냅샷)을 따른다.

### 5. AI 분류와 목적 연결

AI 분류는 공용 taxonomy와 해당 사용자의 AI 후보 허용 사용자 전용 세부 카테고리 안에서만 수행한다. AI는 사용자가 이미 만든 목적에만 새 상품의 연결 가능성을 판단하며, 사용자 의도를 추정해 새 목적·제안 문구를 만들거나 자동 구매 결정을 하지 않는다.

AI가 목적을 자동 연결하려면 상품명·카테고리 등 상품을 식별할 정보와 목적의 이름·설명 또는 기존 포함 상품에 기반한 연결 근거가 있어야 한다. 최소 근거를 충족하는 목적이 여러 개면 가장 부합하는 하나를 연결해 검토 대상으로 표시하고, 어떤 목적도 근거를 충족하지 못하면 `목적 미지정`으로 둔다.

AI가 연결했고 사용자가 아직 확정하지 않은 목적만 상품 정보나 기존 목적 정보가 의미 있게 바뀌었을 때 다시 판단할 수 있다. 사용자가 한 번 확정한 목적은 해당 목적이 삭제되거나 사용자가 직접 수정하지 않는 한 AI가 자동으로 바꾸지 않는다. 목적 삭제로 `확정된 목적 미지정`이 된 상품도 자동으로 다른 목적에 재연결하지 않는다. 새 목적을 만들어도 기존 상품 전체를 자동 재판단하지 않는다. 향후 범위는 [제품 개요의 향후 범위](overview.md#향후-범위)를 따른다.

## 상태와 전환

### `분류·목적 확인`

저장 흐름은 별도 질문이나 확인을 강제하지 않는다. 새 항목의 처리가 끝나 카테고리 또는 목적의 자동 연결 결과를 아직 확인하지 않았으면 `분류·목적 확인`에서 결과를 유지·수정·해제할 수 있다. 중복 후보가 있으면 같은 검토에서 기존 항목과 비교한다.

오른쪽 스와이프는 현재 카테고리·목적 연결을 `확정`하고, 왼쪽 스와이프는 `보류`한다. 스와이프를 사용할 수 없는 경우에는 같은 동작을 하는 명시적 버튼을 제공한다. 보류한 항목은 이 영역에 자동 재노출하지 않으며, 일반 목록 카드에서 미확정 상태를 표시한다. 검토 상태는 일반 목록 사용을 막지 않는다.

`분류·목적 확인`의 공통 의미는 [상품 상태 용어](references/item-states.md)를 따른다. 이 문서는 그 상태를 만드는 검토·정리 행동을 소유하고, 일반 목록의 정보 충족·표시 조건은 상품 확인 흐름에 둔다.

## 예외와 복구

### 중복 후보 비교와 정리

같은 사용자의 활성 목록에 동일한 canonical URL 또는 같은 상품으로 보이는 항목이 있어도 새 항목을 먼저 만든다. 중복 후보 때문에 저장을 차단하거나 두 항목을 자동 병합하지 않는다. 새 항목의 추출이 끝난 뒤 기존 항목과 중복 가능성을 안내하고, 처음에는 다른 URL처럼 보였더라도 추출 뒤 canonical URL이 같아지면 같은 검토 흐름을 적용한다.

기존 항목의 처리 상태에 따라 후보 안내를 다음처럼 구분한다. 상태 용어의 공통 정의는 [상품 상태 용어](references/item-states.md)에 둔다.

| 기존 항목 상태 | 중복 후보 처리 |
| --- | --- |
| `PROCESSING` | 상품을 판단할 정보가 부족하므로 추출이 끝날 때까지 판단을 미룬다. |
| `READY` | 동일한 canonical URL 또는 같은 상품으로 확인되면 중복 후보로 표시한다. |
| `PARTIAL` | canonical URL 또는 현재까지 추출된 정보로 동일성이 확인되면 중복 후보로 표시한다. |
| 분석 실패 | 같은 canonical URL만으로 같은 상품이라고 확정하지 않고, `동일한 URL로 저장된 항목이 있음`을 안내한다. |

사용자는 새 항목을 삭제하거나, 기존 항목을 삭제하거나, 두 항목을 모두 유지할 수 있다. 기존 항목 삭제를 고르면 연결된 목적 등 삭제 영향을 검토 화면에서 알린다. 중복 후보가 있는 항목도 `확정` 또는 `보류`로 검토를 끝낼 수 있으며, 끝난 중복 판단만 다시 여는 별도 동선은 제공하지 않는다.

같은 상품이 아카이브에만 있으면 기존 아카이브를 복원하거나 바꾸지 않고 새 활성 항목을 만든다. 과거의 동일 상품이 삭제된 경우도 새 활성 항목으로 처리한다.

## 제품 규칙

- 공용 taxonomy의 구체적인 11개 상위 카테고리와 87개 세부 유형, 그리고 출시 후 확장 근거는 [상품 taxonomy](references/product-taxonomy.md)가 단독으로 소유한다.
- 카테고리·목적의 연결 및 중복 해소는 사용자의 선택을 우선한다. AI 결과와 중복 탐지는 사용자 선택을 대체하지 않는다.
- 저장 중 중복 후보의 탐지와 분석 상태의 생성·복구는 [상품 저장](save-a-product.md)이 소유한다. 이 문서는 저장을 다시 정의하지 않는다.

## 미결정 사항

- 사용자 전용 카테고리를 추가할 수 있는 기본 흐름과 목적 생성·연결 진입점, 카테고리와 목적의 축·연결 불변 조건에는 원본 스펙의 제안 근거가 남아 있어 문서 상태를 `제안`으로 둔다.
- 목적의 정렬 순서, 여러 검토 항목의 일괄 처리 범위와 노출 시점은 아직 결정하지 않았다.
