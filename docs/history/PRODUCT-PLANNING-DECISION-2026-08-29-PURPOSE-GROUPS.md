# 제품 결정: 목적별 비교 그룹과 AI 목적 제안 (2026-08-29)

> 상태: **대체됨** · 날짜: 2026-08-29 · 영역: **제품 공통**

후속 제품 논의에서 목적 생성·보류·아카이브 흐름을 구체화해 이 문서의 일부 규칙을 대체했다. 현재 기준은 [2026-09-04 기획 체크포인트](PRODUCT-PLANNING-CHECKPOINT-2026-09-04.md)와 [제품 기능 및 스펙](../product-spec.md)이다.

## 결정 내용

- MVP부터 사용자가 상품을 목적별로 묶어 비교할 수 있도록 한다.
- 상품 유형 분류와 목적별 그룹은 서로 다른 축으로 관리한다.
- 상품은 처음 등록할 때 상품 유형을 우선 분류한다.
- 목적 그룹은 이름을 필수로 하고, 설명과 아이콘을 선택적으로 입력할 수 있다.
- 상품 하나에는 목적을 최대 하나만 연결한다. 목적은 필수가 아니다.
- 목적은 사용자가 만든 목적 그룹을 기준으로 AI가 후보를 제안한다.
- 현재 목적 그룹 중 AI 신뢰도가 가장 높은 값을 임시 목적값으로 사용한다. 적절한 후보가 없으면 목적 없이 둔다.
- 상품을 공유해 추가하면 목적 점검 상태는 `NEW`가 된다.
- `NEW` 점검 화면에서 사용자는 AI 목적을 확인하고 목적을 수정·추가·삭제할 수 있다.
- 오른쪽 스와이프는 점검 화면의 현재 목적값을 저장하고 목적 점검 상태를 `CONFIRMED`로 바꾼다.
- 왼쪽 스와이프는 점검을 스킵하고 AI가 최초 유추한 목적을 적용한 뒤 목적 점검 상태를 `UNCONFIRMED`로 바꾼다.
- `UNCONFIRMED` 항목은 일반 목록에 표시하되 상품 카드에 레드닷이나 뱃지 등으로 미확정 상태를 보여준다.
- `NEW` 항목은 목적별 비교 목록에 바로 표시하지 않는다.
- 사용자는 앱 진입 시 짧은 검토 흐름에서 제안을 수락하거나, 다른 목적을 선택·추가하거나, 확인을 스킵할 수 있다.
- 사용자의 선택은 AI 결과보다 우선한다.

## 배경과 판단

상품 정보만으로 사용 목적을 100% 신뢰성 있게 결정하기는 어렵다. 반면 사용자가 만든 목적명과 기존에 해당 목적에 넣은 상품 사례가 있으면 AI는 사용자 맥락에 맞는 후보를 제안할 수 있다.

따라서 목적을 전역 taxonomy처럼 자동 확정하지 않고, 사용자별 목적 그룹에 대한 보조 제안으로 다룬다. 확인 전에는 목적별 목록에 바로 노출하지 않지만, 사용자가 확인을 스킵하면 AI 목적을 미확인 상태로 적용해 목록에 표시한다.

## UX 원칙

- 정상적인 경우 AI 제안 수락은 한 번의 탭으로 처리한다.
- 오른쪽 스와이프는 현재 화면의 목적값 확정, 왼쪽 스와이프는 확인 스킵으로 처리한다.
- 오른쪽 스와이프 전에 목적을 수정·추가·삭제했다면 변경된 값을 확정한다.
- 왼쪽 스와이프는 화면의 편집값과 관계없이 AI가 최초 유추한 목적을 미확정 상태로 적용한다.
- 확인 스킵은 목적 미지정이 아니라 AI 목적을 미확정 상태로 적용하는 동작이다.
- 다른 목적 선택과 목적 추가는 같은 짧은 흐름 안에서 제공한다.
- 목적 확인 때문에 상품 정보 편집 화면을 강제로 거치게 하지 않는다.
- 미확인 목적은 상품 카드의 뱃지나 표시 점으로 쉽게 식별할 수 있어야 한다.
- 여러 항목이 쌓였을 때 개별 화면을 반복해서 열지 않고 연속 또는 일괄 처리할 수 있어야 한다.
- 확인 전 항목의 존재는 앱 진입 시 알려주되, 탐색을 막는 강제 모달은 피한다.

## 남은 결정

- 목적 그룹의 정렬 순서가 필요한지
- 확인 대상의 일괄 처리 범위와 노출 시점
- 목적 후보가 전혀 없을 때의 기본 행동
