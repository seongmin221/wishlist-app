# 제품 결정: 상품 링크 웹뷰 동작

> 상태: **확정** · 날짜: 2026-09-05 · 영역: **제품·클라이언트**

## 결정

- 모든 상품 링크는 상품 처리 상태와 관계없이 앱 내 웹뷰로 연다.
- iOS와 Android 모두 웹뷰를 앱 navigation 화면으로 열고, 닫으면 이전 앱 화면과 상태로 돌아간다.
- 닫기는 좌측 상단에 둔다.
- 뒤로 가기와 앞으로 가기는 좌측 하단에 둔다.
- 새로고침과 공유는 우측 하단에 두며, 공유 메뉴에 외부 브라우저로 열기를 포함한다.
- 양 플랫폼 모두 뒤로 가기는 웹페이지 방문 기록을 우선하고, 기록이 없으면 웹뷰를 닫는다.
- 웹페이지가 새 창을 요청하면 별도 창을 만들지 않고 현재 웹뷰에서 연다.
- 사용자가 직접 누른 링크가 외부 앱을 요청하면 실행을 허용한다. 사용자 동작 없이 자동으로 외부 앱을 열려고 하면 확인을 받는다.
- 웹뷰 쿠키는 방문 간 유지하고 앱 설정에서 웹뷰 데이터를 삭제할 수 있게 한다.
- 외부 앱으로 이동했다가 돌아오면 열려 있던 웹뷰와 방문 기록을 유지하며 강제로 새로고침하지 않는다.
- 결제 완료를 자동 감지해 구매 확정이나 아카이브를 수행하지 않는다.

## 탐색 상태 구분

- 사용자가 웹뷰의 닫기를 선택하면 웹뷰를 열기 전 앱 화면으로 돌아간다.
- 웹뷰를 닫지 않고 결제 앱 등 외부 앱으로 이동한 경우에는 복귀 후 웹뷰를 계속 표시한다.
- OS가 앱 프로세스를 종료한 경우에는 최소한 원래 상품 URL과 앱 navigation 위치를 복원할 수 있게 설계한다.

## 판단 근거

상품의 처리 상태가 좋지 않아도 원본 링크는 사용자가 직접 정보를 확인할 수 있는 최후의 수단이다. 따라서 모든 상태에서 일관되게 접근할 수 있어야 한다.

두 플랫폼의 탐색 배치와 뒤로 가기 규칙을 맞추면 사용자가 기대할 수 있는 동작이 단순해진다. 새 창을 현재 웹뷰에서 열면 별도 탭 관리 없이 방문 기록으로 원래 페이지에 돌아갈 수 있다.

외부 결제 앱 실행과 결제 완료 판단은 서로 다른 문제다. 사용자가 요청한 외부 앱 이동은 허용하되, 위시리스트 앱이 쇼핑몰의 결제 결과를 신뢰성 있게 알 수 없으므로 구매 결정은 사용자가 직접 수행한다.
