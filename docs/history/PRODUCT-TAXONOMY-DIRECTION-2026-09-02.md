# Product taxonomy 방향 정리 (2026-09-02)

> 상태: **확정된 방향 + 남은 세부 설계** · 날짜: 2026-09-02 · 영역: **제품 공통**

제품 분류 체계와 비교 묶음의 관계를 논의하며 합의한 방향과 남은 결정을 기록한다. 기준 스펙은 [제품 기능 및 스펙](../product-spec.md)이다.

## 현재 방향

- 상품 분류는 상위 카테고리와 세부 상품 유형(leaf category)의 계층으로 구성한다.
- 첫 출시 공용 taxonomy는 상위 카테고리 11개와 세부 유형 87개로 확정했다. 이후에는 실제 사용자 로그의 미분류, 반복 커스텀 카테고리, 반복 수동 수정 패턴을 근거로 새 공용 분류를 추가한다.
- 현재 공용 taxonomy에 없는 상품은 사용자가 자신의 위시리스트 안에서 쓸 사용자 전용 세부 카테고리로 추가할 수 있다. 사용자는 상위 카테고리를 선택해야 하며, 이는 공용 taxonomy 변경과 다르다.
- 커스텀 세부 카테고리 생성은 이름만 필수로 하고, 짧은 설명과 포함 예시는 선택 입력으로 둔다. 사용자가 입력한 카테고리에 수정·재입력 절차를 요구하지 않는다. 서버는 과도한 생성과 안전하지 않은 텍스트를 제한하며, AI 입력에 부적합하거나 안전하지 않은 카테고리는 AI 후보에서만 내부적으로 제외할 수 있다. 제외된 카테고리도 개인 목록에는 유지한다.
- 목적은 사용자가 상품을 비교하는 이유를 나타내는 사용자 전용 비교 묶음으로 둔다. 사용자가 먼저 만든 목적에 대해 AI가 새 항목의 연결 가능성을 판단한다.
- AI가 사용자 의도를 추정해 새 목적을 자동 생성하거나, `~는 어떤가요?` 같은 제안형 UX를 만드는 방식은 우선 지양한다. 기존 목적과의 연결 확신이 낮으면 목적 미지정으로 남기고 사용자가 정한다.
- 목적은 목적 탭의 `목적 추가`에서 만들고, 상품 목록에서 포함 항목을 선택한다. 새 항목의 `분류·목적 확인`과 상품 정보 편집 화면에서도 기존 목적 선택·새 목적 생성·목적 변경을 할 수 있다.
- 활성 항목은 카테고리 하나와 목적 0~1개를 가진다. 빈 목적은 자동 삭제하지 않는다.
- 새 항목의 저장 과정에서는 확인을 강제하지 않는다. 처리 뒤 기본 진입 화면에서 카테고리와 목적의 연결 결과를 확인·수정할 수 있게 한다. 오른쪽 스와이프는 확정, 왼쪽 스와이프는 보류이며, 보류 항목은 재노출하지 않고 목록에 미확정으로 표시한다.
- 구매 결정 시 목적과 해당 목적의 모든 후보를 함께 아카이브한다. 개별 후보를 복원해 다른 목적에서 다시 고려할 수 있으며, 원래 아카이브 기록은 보존한다.
- taxonomy 개편과 기존 항목의 마이그레이션은 현재 우선순위에 넣지 않는다.

## 초기 세부 유형 경계

- `헤드폰`에는 게이밍 헤드셋을 포함한다.
- `의자`에는 사무용·게이밍·식탁 의자를 함께 둔다.
- 뷰티의 `스킨케어`와 `메이크업`은 분리한다.
- `키보드`는 하나의 세부 유형으로 둔다.

## 남은 제품 결정

1. 사용자 전용 카테고리의 이름 변경·삭제와, 서버의 안전성 제한·AI 후보 제외의 구체적인 기준
2. 비어 있지 않은 목적을 사용자가 삭제할 때 포함 항목을 어떻게 처리할지
3. AI가 기존 목적에 자동 연결할 최소 근거와, 자동 연결 결과의 재확인 조건

## 권장 순서

먼저 고정 taxonomy의 사용자 표시명과 경계를 확정한다. 다음으로 사용자 전용 카테고리를 그 계층 아래에 추가하는 규칙을 정한다. 이후 예시 위시리스트와 사용자가 만든 목적을 놓고, AI의 기존 목적 연결 품질과 확인 흐름을 평가한다.
