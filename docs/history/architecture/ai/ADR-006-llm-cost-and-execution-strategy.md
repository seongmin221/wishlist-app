# ADR-006: LLM 비용과 실행 전략을 분리한다

> 상태: **부분 대체됨** · 날짜: 2026-09-19 · 영역: **AI·인프라**

> 실행 위치와 기본 모델에 관한 결정은 [ADR-010](ADR-010-openai-low-cost-model-strategy.md)으로 대체됐다. 외부 API 비용을 기본 인프라 예산에서 분리하고 adapter 경계를 유지한다는 결정은 계속 적용한다.

## 맥락

초기 AI 설계는 외부 LLM API를 전제로 했다. 그러나 상품 분류와 목적 연결에서 반복되는 외부 호출 비용을 최소화하고, 가능하면 로컬에서 실행하는 모델을 활용하려는 방향이 추가됐다. 동시에 API·Worker·Queue 호스팅을 선택하려면 월 30,000원 예산에 어떤 비용이 들어가는지 먼저 고정해야 한다.

## 결정

- 월 30,000원 상한은 Neon, Firebase, Ktor API, Worker와 Queue 같은 기본 인프라에 적용한다.
- 외부 LLM API 사용료는 기본 인프라 예산에서 제외하고 별도로 추적한다.
- 외부 LLM 호출은 최소화하며, 요구 품질과 운영 조건을 충족할 수 있다면 로컬 실행 모델을 우선한다.
- AI 분류 모듈은 실행 방식과 공급자에 종속되지 않는 adapter 경계를 유지한다.

`로컬 LLM`이 모바일 on-device 실행을 뜻할지, 서버 자체 호스팅을 뜻할지는 이번 결정에 포함하지 않는다. 모델 선택, 실행 위치와 외부 LLM fallback 조건은 별도 검증 후 확정한다.

MVP에서 자체 모델 학습과 GPU 운영을 하지 않는 기존 원칙은 유지한다. 서버 자체 호스팅 후보가 GPU 운영을 요구한다면 그 원칙을 별도 결정으로 재검토하기 전에는 채택하지 않는다.

## 이유와 trade-off

- 외부 LLM 사용량 변동이 기본 서비스 가용성 예산을 잠식하지 않게 한다.
- deterministic parsing과 캐시를 먼저 사용하고 필요한 분류만 수행하는 기존 원칙과 맞는다.
- 로컬 모델은 호출 단가와 외부 의존성을 낮출 수 있지만, on-device에서는 앱 크기·메모리·배터리 제약이 있고 서버 자체 호스팅에서는 compute·배포·관측 비용이 생긴다.
- 외부 API를 완전히 금지하지 않아 로컬 모델이 품질이나 운영 조건을 충족하지 못할 때 대안을 유지한다.

## 재검토 조건

- 후보 로컬 모델이 taxonomy 분류와 목적 연결의 품질 기준을 충족하지 못한다.
- on-device 모델이 지원 기기 범위, 앱 크기, 응답 시간 또는 배터리 기준을 충족하지 못한다.
- 서버 자체 호스팅 비용이 외부 API 비용보다 높거나 월 기본 인프라 예산을 위협한다.
- 개인정보, 모델 라이선스 또는 배포 정책이 선택한 실행 방식을 제한한다.
