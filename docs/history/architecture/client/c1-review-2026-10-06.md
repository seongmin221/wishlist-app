# C1 리뷰 수정과 검증 (2026-10-06)

사용자 리뷰에 따라 C3 목록 구현 전에 입력 제한, 공유 요소 저장소, 라우터 책임, 접근성과 반복 렌더링 경로를 보완한다. 현재 구조와 API는 [디자인 시스템](../../../architecture/client/design-system.md)을 따른다.

## 첫 리뷰 구현 (추가 리뷰에서 일부 API 재수정)

- 입력은 초과 편집을 거부하는 대신 확정 문자열을 grapheme 경계에서 자른다. 조합·선택을 보존하며 붙여넣기는 허용 길이까지 남긴다. 초기 값·길이 제한 변경도 다시 맞춘다. Android는 `TextFieldValue`, iOS는 Binding + `onChange`와 UIKit marked text 탐침이다.
- iOS `WLText` 기본 경로는 한 줄 SwiftUI `Text`다. 여러 줄 상품명·설명·확인창 본문은 `multiline: true`로 지정했다. UIFont는 크기·이름 키의 NSCache(128개 상한)로 재사용한다.
- iOS 사진 builder·면 spec은 탐침 갱신 때 교체하고 window 이탈 때 해제한다. 숨김은 key별 관찰 객체이며 잠시 분리되는 동안 정체성을 유지하고 최종 dismantle 때 제거한다. Android는 소유자 lease로 등록·해제하고 같은 값은 다시 쓰지 않는다. 공유 면의 draw cache에서 애니메이션을 읽으며 기존 그림자 blur/y/alpha를 유지한다.
- feature가 경로·전환 방식·탭 바 정책을 제공하고 core의 데모 id 파싱을 제거했다. Android는 현재 탭과 스택·전환을 snapshot 상태로 통일했다. iOS navigator·motion은 앱 루트 소유다. 데모 코드와 renderer는 Android debug source set, iOS `#if DEBUG`로 제한했다.
- iOS overlay 완료는 애니메이션 completion으로 알리며, 두 플랫폼 모두 열고 닫는 층을 접근성에서 숨긴다. iOS Reduce Motion, 펼침 높이 애니메이션, Android 선택·펼침 상태 의미를 반영했다. Android 입력의 contentDescription 덮어쓰기도 제거했다.
- Android drag는 delta마다 coroutine을 만들지 않고 상태를 직접 갱신한다. 높이는 `onSizeChanged`, 메뉴 anchor는 누를 때 조회, 제한 Density는 remember로 유지한다. iOS 색 보간은 `UIColor.getRed`로 색 성분을 얻고 레이아웃의 미지정 폭은 intrinsic 크기를 따른다.
- ISO 통화 소수 자릿수(JPY 0, USD 2, KWD 3), EmptyState em 줄 높이와 오래된 주석을 수정했다. Android Masonry는 유한 폭이 필수라는 계약을 명시적으로 검사한다. 가로 스크롤 호출자는 폭을 지정해야 한다.

독립 리뷰에서 추가로 발견한 같은 key의 옛 소유자 dispose, temporary window detach 뒤 숨김 객체 교체, 탭 변경 뒤 캡처한 이전 탭 참조, 테마 변경 뒤 오래된 공유 면 색, 입력의 초기 값 누락도 보완했다.

## 토큰과 CI

- `hex_int`는 문자열 `#RRGGBB`만 받는다. 짧은 RGB·8자리·잘못된 hex·형식 없는 값은 `ValueError`로 즉시 실패한다. Swift RGB와 Android 불투명 ARGB가 같은 색을 생성한다.
- 잘못된 색 8종이 기존 구현에서 실패하지 않는 것을 회귀 테스트로 먼저 확인했다. 수정 후 Python 8개 테스트와 생성물 `--check`가 통과했다.
- `.github/workflows/client-checks.yml`: 클라이언트·모션 토큰 변경의 PR·develop push와 수동 실행에서 토큰 검사 → Android/iOS 검증을 수행한다. Android는 Debug/Release 단위 테스트·빌드와 lint, iOS는 arm64 simulator 테스트와 Release 빌드다. workflow 정적 검사(`actionlint`)가 통과했다. GitHub 원격 실행 결과와 branch protection의 required check 지정은 아직 확인하지 않았다.
- Action은 확인한 tag의 commit SHA로 고정한다. iOS는 KMP의 `iosSimulatorArm64` 경계에 맞춰 `macos-15` arm64와 Xcode 26.0.1을 선택했다. 근거: [GitHub runner 이미지](https://github.com/actions/runner-images), [macOS 15 arm64 설치 도구](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-arm64-Readme.md), [Gradle setup](https://github.com/gradle/actions/blob/main/setup-gradle/README.md).

## 글꼴 용량 검토

각 플랫폼의 원본 TTF 합계는 **9,419,184 bytes**다(압축된 APK/앱 다운로드 크기와 다르다). Do Hyeon 879,764와 Plex KR Regular 2,797,100 / Medium 2,866,736 / Bold 2,875,584 bytes다.

이번 수정에서는 원본 번들을 유지한다. 사용자 입력인 상품명·목적명·설명은 미리 문자를 확정할 수 없으므로 화면 데모에 있는 문자만 남기는 서브셋은 사용할 수 없다. 다운로드 글꼴은 첫 실행·오프라인에서 폰트와 글자 측정 결과가 달라지며 로딩·캐시·실패 정책이 필요하다. C1 안정화에서 이 정책을 새로 도입하지 않는다.

C3의 실제 목록·입력 사례를 확보하면 한글 완성형·자모, 영문·숫자·기호·통화, 결합 문자 범위를 보존한 서브셋을 시험한다. 기존 글꼴과 fallback의 스크린샷·줄 높이·앱 패키지 크기를 비교하고, 라이선스 파일과 글꼴 naming을 유지하는 생성 절차까지 검증한 뒤 교체한다. 배포 방식 선택과 현재 렌더링 경로 성능 검증은 별개다.

## 후속 확인

- 실제 기기 한글 IME: 39/40자에서 조합·삭제·커서 이동, 한도 초과 붙여넣기와 이모지/결합 문자.
- iOS 입력 탐침은 같은 window의 native 입력과 field frame의 겹침으로 조합 소유를 확인한다. 나란한 입력은 구분하지만 overlay 입력과 유지된 배경 입력이 같은 위치에 겹치면 둘 다 소유자로 볼 수 있다. 겹친 칸에서의 외부 값 변경·조합을 실기기에서 확인하고 실제 feature에서 필요하면 native field identity로 보완한다.
- TalkBack: 입력한 내용·라벨·편집 상태를 함께 읽는지, 선택된 칩·펼침 상태를 읽는지.
- VoiceOver: overlay 전환 중 클릭 차단, 상세 진입 포커스·escape, Reduce Motion 켠 상태의 전환 종료.
- C3 목록: 수십 카드 스크롤의 메모리·렌더 횟수, 이미지 교체와 화면 제거 후 registry 해제.
- Android navigator는 아래 추가 리뷰에서 저장·복원했다. iOS navigator와 UI 람다를 보유한 overlay의 저장·복원은 feature 데이터 모델을 도입할 때 설계한다.

## 추가 리뷰 수정

- 앱 루트가 두 플랫폼의 navigator와 필요한 motion/registry를 OverlayHost 바깥에 제공한다. 시트·메뉴·확인창에서 같은 이동 API를 사용할 수 있으며 누락된 환경 값은 즉시 실패한다.
- Android navigator saver는 현재 탭, feature route codec, 스택의 entry id·sourceKey, nextId를 저장한다. 전환은 복원 시 완료 상태로 정리한다. SaveableStateHolder 정리 대상 목록도 저장해 회전 뒤 새 상세가 이전 상세의 저장 상태를 받거나 제거된 칸의 상태가 남는 문제를 막았다. 복원 뒤 push의 ID 증가를 회귀 검사했다.
- Android WLInput은 단일 TextFieldState API로 바꿨다. snapshotFlow로 조합·텍스트를 관찰하며 조합 중에는 보존하고 확정 뒤 grapheme 경계에서 자른다. 현재 Compose InputTransformation의 incoming composition API가 internal이고 composition-only commit은 transformation을 통과하지 않아 commit 관찰을 사용했다. 호스트 JDK 검증과 API 26 ICU·실기기 한글 IME 확인은 별개다.
- WLText는 두 플랫폼 모두 maxLines 기본 무제한이다. iOS는 상위 lineLimit도 따르며 유효 제한이 1인 버튼·칩·탭 등만 native Text로 그린다. 여러 줄은 기존 정확한 줄 높이 UILabel 경로를 유지한다.
- 통화 코드는 trim·대문자로 정규화하고 알 수 없는 코드와 음수 자릿수 메타데이터는 2자리로 표시한다. iOS는 전체 ISO 목록의 소수 자리 캐시를 사용한다. CLF 4자리도 확인했다. C2 KMP domain에서 서버 코드 검증을 통합한다.
- Android 공유 면은 matched source만 애니메이션·painter를 만든다. painter 객체는 재사용하고 outline은 draw마다 갱신한다. 기존 blur·그림자 위치·alpha를 유지한다. matching probe와 renderer/outline 비용은 C3에서 측정한다.
- Android AppRoute·AppRouteCodec은 main에 하나만 두고 데모 renderer·codec만 variant hook으로 제공한다. finishTransition은 모듈 내부로 제한하고 wlLineBox 높이는 constraints로 제한한다. 같은 Gradle 모듈 안에서는 feature 접근까지 차단되지 않는 점을 모듈 검토에 남겼다.
- iOS Masonry는 Layout cache를 쓴다. 입력 조합 감지는 앱 공용 UIKit 알림 관찰자와 window별 약한 responder cache로 바꿔 입력칸별 관찰자·키 입력마다 전체 트리 탐색을 없앴다. 최초 window 탐색과 겹친 입력 소유 한계는 남아 있다.
- 두 플랫폼의 닫기·시트·메뉴·펼침/접힘·탭 이름은 한영 리소스로 옮겼다. showSheet 제목을 실제 접근성 pane 이름에 쓰며 Android chip은 selectable로 선택 상태를 제공한다.

CI는 develop push·PR만 자동 실행하여 PR 브랜치의 중복 push 실행을 제거했다. iOS 17.5/26.0 matrix를 같은 Xcode 26.0.1에서 돌리며 필요한 runtime을 준비하는 스크립트를 추가했다. 설치됨·다운로드 성공·다운로드 실패·설치 후 runtime 없음의 4개 mock 경로를 확인했다. 실제 GitHub runtime 설치·테스트 실행은 아직 확인하지 않았다. 새 workflow는 로컬 변경이며 원격 실행 이력이 없으므로 원격 검증 성공으로 간주하지 않는다.

C3의 유지된 iOS 탭·스택 메모리/레이아웃, 입력 responder 경로, Android shared 요소 비용과 Gradle 모듈 분리 검토는 [성능·구조 확인 목록](../../../architecture/client/c3-performance-checks.md)에 기록했다. 이 체크리스트는 측정 결과가 아니다.

## CI 첫 실행 수정 (2026-10-07)

PR #7의 첫 `Client checks` 실행에서 세 job이 실패했다.

- android: ubuntu 러너 PATH에 `sdkmanager`가 없다. 러너에 android-36·build-tools 36.0.0이 이미 있어 설치 단계를 지웠다.
- ios 26.0: 러너의 iOS 26.0 시뮬레이터 런타임 버전 문자열은 `26.0.1`이라 정확히 `26.0`을 찾던 준비 스크립트가 다운로드로 넘어가 실패했다. matrix를 `26.0.1`로 바꿨다.
- ios 17.5: `testMultilineTextReadsAsOneStaticText`가 빈 접근성 트리를 받고 `found[0]`에서 테스트 프로세스가 죽었다. SwiftUI는 앱 접근성이 켜져 있을 때만 요소를 만든다. 로컬에서 같은 테스트가 설정 없이는 `6b1d522`·HEAD 모두 실패하고, `ApplicationAccessibilityEnabled`를 켜면 둘 다 통과했다. CI에서 테스트 전에 이 설정을 켜고, 테스트는 요소가 없을 때 색인 접근 전에 멈춘다.

두 번째 실행에서 tokens·android(약 4분)·ios 17.5(약 15분, 시뮬레이터 내려받기 포함)는 통과했고, ios 26.0.1은 빌드가 끝난 뒤 시뮬레이터 설치·실행 단계에서 로그 없이 멈춰 60분 제한으로 취소됐다(부팅 완료를 기다리지 않은 것이 유력하나 미확정). PR마다 10분 이상 걸리는 병목이라 사용자 결정으로 android·ios job의 자동 실행을 끄고 수동 실행(`workflow_dispatch`)에서만 돌게 했다. tokens job은 계속 PR·develop push에서 돈다. 다시 켤 때는 iOS 부팅 완료 대기(`simctl bootstatus -b`), 단계 시간 제한, 플랫폼별 경로 분리, Kotlin/Native 캐시를 함께 검토한다.
