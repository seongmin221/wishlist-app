# ADR-001: 프로젝트 문서와 구현 이력을 작업 중 함께 기록한다

> 상태: **확정** · 날짜: 2026-08-27 · 영역: **프로젝트 공통**

## 맥락

이 프로젝트는 모바일 개발 경험을 기반으로 서버와 AI 영역까지 새로 설계·구현한다. Git commit은 코드의 변경 내용을 보존하지만, 변경의 계기, 검토한 대안, 선택의 이유와 향후 재검토 조건까지 충분히 전달하지는 못한다.

기획, 설계, 학습, 구현 이력이 Codex 세션 진행 중에도 저장소의 Markdown 문서에 계속 축적되기를 원한다. 문서는 GitHub 및 향후 GitHub Pages에서 확인할 수 있어야 한다.

## 결정

- 저장소 루트의 `AGENTS.md`에, 의미 있는 작업이 끝나기 전에 관련 `docs/` 문서를 갱신하도록 짧고 지속적인 지침을 둔다.
- 상세 작성 규칙과 양식은 `AGENTS.md`가 아니라 `docs/README.md`와 `docs/history/`에 둔다.
- Codex project-local `PostToolUse` hook은 구현 파일 수정 뒤 문서화 필요 여부를 상기시킨다. 이 hook은 기록을 강제하거나 자동으로 의미를 요약하지 않는다.
- 의미 있는 구현 변경의 사유와 trade-off는 `docs/history/`에 기록한다. 이력은 해당 변경이 속한 `client`, `server`, `ai` 폴더에 두며, 여러 영역에 걸친 작업 방식 결정은 history 루트에 둔다.
- Git은 실제 코드 diff와 commit의 원본 이력으로 유지한다. history 문서는 Git을 복제하지 않고, 코드만으로 알기 어려운 의도와 판단을 기록한다.

## 기록 대상

다음 중 하나에 해당하면 문서화를 검토한다.

- 사용자에게 보이는 동작 또는 제품 정책의 변경
- 데이터 흐름, 모듈 경계, 외부 서비스, 보안·재시도 정책의 변경
- 새 기술 또는 의존성의 채택·교체
- 재발 방지 가치가 있는 버그 분석과 해결책
- 대안 사이에서 감수한 trade-off

포맷팅, 이름 변경, 명백한 오타 등 기계적이고 자명한 수정은 history 기록 대상이 아니다.

## 선택지와 trade-off

### AGENTS.md만 사용

가장 단순하지만, 구현 파일을 수정한 뒤 문서화 검토 자체를 놓칠 가능성이 있다.

### Hook만 사용

파일 변경 이벤트는 감지할 수 있지만, hook은 변경 사유나 학습 가치 같은 문맥을 신뢰성 있게 판단할 수 없다. 세션 transcript를 자동 요약해 Git에 남기는 방식은 민감한 프롬프트 유출, 불안정한 transcript 형식, 과도한 로그 생성 위험이 있다.

### AGENTS.md + 알림 hook + Git 이력

문서의 의미와 분류는 Codex가 작업 맥락으로 판단하고, hook은 누락을 줄이는 보조 장치가 된다. Git은 코드의 정확한 변경 이력을 유지한다. 이 조합을 채택한다.

## 재검토 조건

- 문서화가 반복적으로 누락되면 CI 또는 commit-time check를 경고 모드로 추가한다.
- history가 너무 많아 탐색이 어려워지면 기록 기준을 더 좁히거나 분기별 요약 문서를 만든다.
- 여러 프로젝트에서 같은 방식이 필요해지면 repository hook을 개인 또는 팀 단위 Codex plugin/skill로 승격한다.
