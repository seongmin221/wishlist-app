# 제품 결정: 중복 URL과 상품 후보 처리

> 상태: **확정** · 날짜: 2026-09-05 · 영역: **제품·서버**

## 결정

- 같은 사용자의 활성 목록에 동일한 canonical URL 또는 같은 상품으로 보이는 항목이 있어도 새 항목을 우선 생성한다.
- 시스템은 중복 후보라는 이유만으로 저장을 차단하거나 두 항목을 자동으로 병합하지 않는다.
- 새 항목의 추출이 끝나면 `분류·목적 확인` 흐름에서 기존 항목과 함께 중복 가능성을 안내한다.
- 사용자는 새 항목 삭제, 기존 항목 삭제, 두 항목 모두 유지 중 하나를 선택할 수 있다.
- 처음에는 다른 URL로 보였더라도 추출 후 canonical URL이 같다고 확인되면 같은 중복 검토 흐름을 적용한다.
- 동일 상품이 아카이브에만 있으면 기존 항목을 복원하지 않고 새 활성 항목을 생성한다. 기존 아카이브 스냅샷은 변경하지 않는다.
- 과거의 동일 상품이 삭제된 경우에도 완전히 새로운 활성 항목을 생성한다.

## 기존 항목의 추출 상태별 처리

- `PROCESSING`: 상품을 판단할 정보가 아직 부족하므로 추출이 끝날 때까지 상품 중복 판단을 미룬다.
- `READY`: 동일한 canonical URL 또는 상품으로 확인되면 중복 후보로 표시한다.
- `PARTIAL`: canonical URL이나 현재까지 추출된 정보로 동일성이 확인될 때 중복 후보로 표시한다.
- `FAILED`: 같은 canonical URL만으로 같은 상품이라고 확정하지 않는다. 대신 `동일한 URL로 저장된 항목이 있음`을 안내한다.

`READY`는 충분한 상품 정보가 추출된 상태, `PARTIAL`은 추출은 끝났으나 일부 정보가 누락된 상태, `FAILED`는 상품 정보 추출을 완료하지 못한 상태다. 이 추출 상태는 사용자가 카테고리와 목적을 확인했는지 나타내는 상태와 별개다.

## 판단 근거

같은 canonical URL이라도 옵션이나 구매 맥락이 달라 사용자가 두 항목을 모두 유지하려 할 수 있다. 반대로 기존 항목보다 새 항목의 정보 품질이 좋을 수도 있으므로 항상 새 항목만 삭제하도록 제한하지 않는다.

추출이 끝나기 전에는 상품 동일성을 판단할 근거가 부족하고, 추출에 실패한 URL도 실제 상품이 같은지 확인하기 어렵다. 따라서 상태에 따라 안내의 강도를 다르게 하되 최종 정리는 사용자가 결정한다.

아카이브는 과거 구매 결정의 기록이므로 새 저장 때문에 복원하거나 변경하지 않는다.

## 제품·구현 영향

- 사용자별 canonical URL에 대해 활성 `WishlistItem` 생성을 막는 유일성 제약을 두지 않는다.
- 중복 탐지는 차단 규칙이 아니라 검토 후보를 만드는 기능으로 구현한다.
- 중복 검토 UI는 새 항목과 기존 항목의 핵심 정보, 상태, 카테고리와 목적을 비교할 수 있어야 한다.
- 기존 항목 삭제를 선택할 수 있으므로 연결된 목적 등 삭제 영향을 검토 화면에서 알려야 한다. 구체적인 삭제 안전장치는 후속 논의에서 정한다.
