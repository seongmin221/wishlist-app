# 제품 기획·학습 재개 체크포인트 (2026-08-29)

> 상태: **진행 중** · 날짜: 2026-08-29 · 영역: **제품 공통**

다음 Codex 세션에서 제품 기획과 기술 학습을 중단 지점부터 재개하기 위한 인수인계 기록이다. 제품 정책의 기준 문서는 [제품 기능·스펙](../product-spec.md)이다.

## 이번 세션에서 확정한 제품 방향

- 앱의 본질은 URL을 모으는 저장소가 아니라, **같은 상품 유형의 구매 후보를 비교하는 위시리스트**다.
- URL 공유 후의 추출 상태와 무관하게, 사용자는 언제나 원본 링크를 앱 내 웹뷰로 열 수 있다.
- AI는 정의된 taxonomy 안에서 카테고리를 자동 지정한다. 저장 흐름에서 확인을 강제하지 않으며, 사용자는 필요할 때만 수정한다.
- 카테고리는 구매 후보를 비교하는 기본 그룹이며, 활성 항목은 **최근 저장순**으로만 정렬한다.
- `PROCESSING`은 링크, 로딩 표시, `상품 정보 추출 중` 문구를 보인다. 추출 완료 항목은 일반 카드로 보이며 내부 `READY` 상태를 별도로 강조하지 않는다.
- 일부 추출 또는 실패 항목은 링크를 열 수 있고, 제품명·대표 이미지·카테고리를 같은 상품 정보 편집 화면에서 직접 보완할 수 있다. 대표 이미지는 MVP에서 사진 보관함에서 선택한다.
- 기본 진입 화면 상단에는 `분류 중`과 `정보 보완 필요` 영역을 둔다. 일반 카테고리 목록보다 먼저 필요한 조치를 보이되, 항목이 없으면 해당 영역은 보이지 않는다.
- 가격은 가능할 때만 추출한다. **원래 금액, ISO 4217 통화, 마지막 확인 시점**을 함께 보이며 실시간 가격으로 보장하지 않는다. 다른 통화로의 환율 환산은 MVP에서 하지 않는다.
- 사용자는 같은 카테고리의 후보를 직접 여러 개 선택하고, 구매한 상품 하나를 지정할 수 있다. 선택한 후보 전체는 아카이브되며, 아카이브 묶음의 기본 제목은 구매한 제품명이고 사용자가 수정할 수 있다.
- 삭제는 아카이브와 별도의 행동이다. 기본 목록에는 아카이브 항목을 보이지 않고, 아카이브에서 과거 구매 결정과 후보를 확인한다.

## 범위와 보류한 결정

### MVP에서 제외

- 추출 작업 재시도 UI
- 가격 변동·품절/재입고 알림과 주기적 상품 재수집
- 환율 환산
- 목적별 비교 컬렉션, 전문 검색, 추천

### 이후 우선순위

- **V1:** 목적별 비교 컬렉션과 검색. 목적별 묶음은 유용하지만, MVP의 상품 taxonomy와 동시에 도입하면 분류 개념이 두 개가 되어 초기 경험을 복잡하게 만든다.
- **V2 이후:** 가격·재고 알림, 주기적 재수집, 선호 통화 기준의 참고 환산. 환산을 도입할 때는 환율 출처, 갱신 시점, 반올림 정책이 필요하다.

## 다음 세션의 권장 재개 순서

1. **taxonomy 초안 작성 (최우선)**
   - 첫 출시의 상위 카테고리와 8~12개 정도의 세부 상품 유형을 정한다.
   - AI가 확신하지 못하면 `정보 보완 필요`에 남긴다.
   - MVP에서는 항목당 카테고리 하나만 허용한다.
2. **상품 정보 보완의 완료 기준 결정**
   - 활성 비교 목록에 들어가기 위해 필요한 최소 필드(권장: 제품명과 카테고리, 이미지는 선택)를 확정한다.
3. **중복 URL 저장 정책 결정**
   - 활성 항목, 아카이브 항목, URL 정규화 결과가 각각 존재할 때 다시 공유한 URL을 어떻게 처리할지 정한다.
4. **아카이브·삭제의 안전장치 결정**
   - 아카이브 직후 되돌리기, 삭제 확인, 아카이브 항목 복원 필요 여부를 정한다.
5. **웹뷰 동작 정의**
   - 뒤로 가기, 외부 브라우저 열기, 결제 뒤 앱 복귀 시의 동작을 정한다.
