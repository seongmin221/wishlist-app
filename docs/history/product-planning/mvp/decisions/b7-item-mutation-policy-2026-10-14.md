# 제품·운영 결정: B7 상품 사용자 변경

> 상태: **확정** · 날짜: 2026-10-14 · 영역: **제품·서버**

B7 착수 대조에서 남은 미결정 규칙을 사용자에게 묻고 확정했다. 일곱 항목 모두 추천안을 택했다. 이 문서는 결정을 기록하며 구현 완료를 의미하지 않는다. 설계는 [B7 spec](../../../../superpowers/specs/2026-10-14-b7-item-mutations-design.md)에서 관리한다.

## 결정 — 사용자 확인 완료

1. **상품명·브랜드 입력 제한.** 상품명은 1~200, 브랜드는 1~200 Unicode code point다. 사용자 category·목적과 같은 `UserTextRules`(한 줄, 제어문자·보이지 않는 방향 제어 문자 거절)를 쓰고 공백만 있는 값은 빈 값으로 본다. 상품명은 빈 값·null로 지울 수 없다. 브랜드는 `null`로만 지우며 빈 문자열은 거절한다. 사용자 category의 내용 안전성 검사(지시문·유해 텍스트)는 적용하지 않고 목적처럼 JSON 데이터 경계로 보호한다. 추출된 기존 값은 사용자가 그 필드를 바꿀 때만 검사한다.
2. **편집 중 만든 category의 수명.** 상품 편집을 취소해도 이미 만든 사용자 category를 지우지 않는다. 목적(B3)과 같다. 생성과 연결을 한 API로 묶지 않는다.
3. **일반 편집의 검토 상태 영향.** ITEM-04가 category 또는 목적을 바꾼 결과, 검토 대기(PENDING)·보류(DEFERRED) 상품에 AI 출처 category와 AI 연결 목적이 하나도 남지 않으면 CONFIRMED로 바꾼다. 하나라도 남으면 검토 상태를 유지한다. 분석 결과 반영의 "미확정 AI 연결이 있어야 PENDING" 기준과 같다.
4. **사용자 사진 해제.** `mediaId: null`로 사진을 해제하면 분석으로 얻은 외부 이미지가 있을 때 그 이미지로 돌아간다(이미지 출처 AI, IMAGE 보호 해제). 외부 이미지가 없으면 이미지 없음이다. 해제·교체한 media는 `unreferenced_since = now`로 두어 24시간 뒤 정리된다.
5. **수동 완료 전 PARTIAL·실패 상품의 PATCH.** B0 정책대로 PROCESSING이 아닌 ACTIVE 상품은 모두 편집할 수 있다. PATCH는 수동 완료 시각을 기록하지 않는다. 정보 보완 저장은 클라이언트가 `MANUAL_COMPLETE`가 허용될 때 ITEM-07로 보낸다. PATCH로 이름·category를 채운 FAILED_RETRYABLE 상품은 계속 재분석할 수 있으며 사용자 값은 보호된다.
6. **재분석 남용 제한.** 신규 재분석 성공은 owner별 직전 60초 10건까지다. 넘으면 429와 `Retry-After`다. 같은 key의 재전송은 세지 않는다. 재분석 key는 계정 데이터가 유지되는 동안 보존한다.
7. **owner 잠금 방식.** B7에서는 `OwnerStructureLock`의 `FOR UPDATE`를 유지한다. B7의 새 쓰기는 모두 owner 잠금을 먼저 잡으므로 충돌이 늘지 않는다. FOR NO KEY UPDATE 전환은 B11 부하 시험에서 경합이 보이면 별도 묶음으로 다룬다.

## 판단 근거

- 200자는 추출 단계의 브랜드·판매처 상한과 같다. 추출 상품명에는 길이·문자 제한이 없으므로, 저장된 값과 같은 값을 다시 보내면 검사하지 않는다. 그래야 줄바꿈이 섞인 긴 추출명을 가진 상품도 이름을 바꾸지 않고 직접 보완을 끝낼 수 있다. 목적 이름(40자)보다 긴 것은 쇼핑몰 상품명이 모델명·옵션을 포함하기 때문이다. 내용 검사를 빼는 이유는 상품명이 AI 분류 후보 목록이 아니라 분석 대상 데이터이고, 사용자가 수동 완료한 상품은 재분석하지 않기 때문이다.
- category 자동 삭제는 제품 문서의 "빈 사용자 category 유지"와 충돌하고, 생성·연결 단일 API는 API 수와 실패 조합을 늘린다.
- 검토 상태 규칙을 분석 반영 기준과 맞추면, 편집 화면에서 모든 자동 값을 사용자가 고친 상품이 분류·목적 확인에 남는 일이 없고, 일부만 고친 상품은 남은 AI 값을 검토할 수 있다. 확정·보류는 계속 ITEM-08이 담당한다.
- 제품 문서에 "이미지 숨기기" 동작이 없다. 사진 해제를 사용자 사진을 쓰지 않겠다는 뜻으로 보고 원래 상품 이미지로 돌아가게 했다. 잘못된 외부 이미지는 사진을 골라 덮어쓸 수 있다.
- PATCH 허용 범위를 바꾸면 B0의 allowedActions 표와 클라이언트 분기가 함께 바뀐다. 수동 완료는 의미가 다른 명령(재분석 제외·CONFIRMED)이므로 별도 API로 유지한다.
- 재분석마다 새 generation 예산(합산 3회·30분)이 생긴다. 전체 일·월 예산 상한이 있어도 한 사용자의 반복 재분석이 다른 사용자의 분석을 막을 수 있으므로 생성 API들과 같은 60초 창으로 제한한다.
- 잠금 방식 전환은 B2~B6의 모든 owner 경로 동시성을 바꾸므로 근거(경합 관측) 없이 이번 묶음에 넣지 않는다.

## 제품·구현 영향

- 구현 순서 문서의 미결정 표에서 "상품명/brand 제한·생성 후 편집 취소"를 해결로 바꾼다.
- [상품 확인과 편집](../../../../product/inspect-and-edit-a-product.md)에 입력 제한·사진 해제 결과를 반영한다.
- [API 목록](../../../../architecture/server/mvp-api-inventory.md)의 CAT-03 "후속 제품 확인 대상" 문구를 확정으로 바꾼다.
