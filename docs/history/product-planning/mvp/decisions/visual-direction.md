# 제품 결정: 시각 디자인 방향

> 상태: **진행 중 (2차)** · 날짜: 2026-09-24 · 최종 갱신: 2026-09-25 · 영역: **디자인·클라이언트**

## 현재 결정

- 앱 문구는 **해요체**로 쓴다. 앱이 할 일은 `~할게요`, 사용자에게 부탁할 일은 `~해 주세요`로 쓰고, 합쇼체·반말·이모지는 섞지 않는다.
- 글꼴은 잠정적으로 한글 Pretendard, 큰 숫자·영문은 Space Grotesk, 라벨은 고정폭(JetBrains Mono)으로 두고 방향이 정해진 뒤 다시 검토한다.
- 1차 시안은 초기화했고, 2차 방향(R-1 에디토리얼 블록)으로 아래 화면을 확정했다.
  - 홈(챙길 일 있음, 빈 홈 3종), 카테고리 탭(목차 → 상세), 목적 탭(목록 → 상세), 목적 상세 동작, 아카이브 목록·기록 상세·동작, 공통 바텀 시트, 공통 상품 목록
- 확정 보드는 디자인 캔버스의 `확정 화면` 페이지에 있고, `통합 흐름` 보드에서 하단 탭과 화면 이동을 이어서 눌러 볼 수 있다. 비교했던 안은 `탐색 · 아카이브 색`, `탐색 · 목적 상세 동작`, `2차 · 탐색 기록` 페이지에 기록으로 남아 있다.
- 색(기초 팔레트·목적 색 활용 확대), 글꼴, 기초 요소는 아직 정리하지 않았다.

## 2차 방향의 기준

사용자가 고른 레퍼런스(에디토리얼 블록형 앱, 큰 숫자의 통계 앱, 스위스 그래픽 스타일 앱, 반투명 설정 앱, 노이즈 그라데이션 데이터 시트)에서 다음을 기준으로 삼는다.

- 크게 쓴 글자와 숫자가 화면의 주인공이 되고, 작은 라벨과 크기 대비가 크다.
- 색은 작은 배지가 아니라 화면 폭의 블록이나 배경 같은 넓은 면으로 쓴다.
- 요소가 적고 블록 안의 빈 공간과 공간 활용이 과감하다.
- 누르면 펼쳐지거나 바뀌는 인터랙티브한 느낌을 준다.
- 깔끔하면서 창의적인 인상을 준다.

R-1 에디토리얼 블록, R-2 스위스 그래픽, R-3 데이터 시트·질감을 홈 화면으로 비교해 **R-1**을 택했다.

### 홈 (확정)

홈 구성은 디자인 캔버스의 `홈 확정 (P-D)` 보드를 기준으로 확정한다.

- R-1 에디토리얼 블록을 더 작은 크기(R-1c 기준: 헤드라인 22px, 블록 숫자 40px, 블록 모서리 20)로 진행한다.
- 하단 탭은 **홈, 카테고리, 목적** 세 개로 두고 새로고침 버튼은 탭에 두지 않는다.
- 홈에는 카테고리 영역을 두지 않는다. 홈은 챙길 일 블록(분류·목적 확인, 정보 보완 필요, 분류 중)만 보여주고, 블록을 펼치면 해당 상품을 사진·이름·가격과 상태별 설명이 있는 가로 목록으로 자세히 보여준다.
- 블록을 펼칠 때의 애니메이션은 보류한다.
- 아카이브는 탭으로 두지 않고, 목적 탭 상단의 전환 버튼으로 `진행 중`과 `아카이브`를 오간다.
- 새로고침은 화면을 아래로 당겨서 한다.
- `분류 중`은 할 일이 아니라 기다리는 상태이므로 챙길 일 블록과 같은 크기로 두지 않고, 챙길 일 블록 맨 아래의 한 줄짜리 블록으로 줄인다. 아이콘 타일·개수·펼침 화살표는 다른 블록과 같은 모양을 쓰고, 펼치면 링크 주소와 원본 열기를 보여준다.
- 제품 규칙대로 항목이 없는 챙길 일 블록은 숨긴다. 블록이 모두 사라진 홈은 두 경우로 나눈다.
  - 챙길 일을 다 끝냈을 때: 고르는 중인 목적 목록과 목적 탭으로 가는 링크를 보여주고, 그 아래에 저장 방법 세 단계를 카드 없이 배경에 스며들듯 옅게 둔다.
  - 목적도 없거나 저장한 상품이 없을 때: 저장 방법 세 단계만 같은 방식으로 보여준다.
- 헤드라인은 두 줄로 쓰고 각 줄은 한 줄 안에 들어가게 짧게 쓴다. 첫 줄은 상태(`챙길 일이 6개 있어요.`), 둘째 줄은 회색 안내(`AI가 정리한 것부터 볼까요?`)다.
- 헤드라인 둘째 줄 색은 기본 바탕에서는 글자색 50% 투명, 목적 색 같은 다른 색 면 위에서는 그 면 색으로 직접 계산한다. 계산 방법은 [헤드라인 둘째 줄 색 계산](../../../../architecture/client/headline-secondary-color.md)을 따른다.
- 헤드라인 줄이 넘치면 말줄임하지 않고 최대 22px에서 글자 크기를 줄여 한 줄에 맞춘다. 구현 시 iOS는 `minimumScaleFactor`, Android는 자동 크기 조절 텍스트를 쓴다.
- 화면을 오가도 좌상단 텍스트의 시작 위치는 같게 둔다. 예를 들어 카테고리 목록의 `● 카테고리`와 상세의 `‹ 카테고리`는 글자가 같은 x에서 시작한다.

### 카테고리 탭 (확정)

디자인 캔버스의 `CT-D 카테고리 탭` 보드를 기준으로 확정한다.


- 첫 화면은 목차형(CT-A)이다. 상위 카테고리를 작은 고정폭 라벨로 묶고 세부 카테고리를 큰 글자 한 줄씩, 사진 겹침과 개수를 붙여 보여준다.
- 목차의 글자는 모두 헤드라인과 같은 20px에서 시작한다. 구분선만 두 가지로 나눈다. 상위 묶음(패션, 잡화, 미지정)을 여는 첫 구분선은 목록 가장자리인 6px까지 넓히고, 세부 카테고리 사이 구분선은 20px 안쪽에 둔다(CI-6B·CI-20 비교 결과).
- 카테고리를 누르면 해당 카테고리의 상품 목록(상단 카테고리 탭 없음)으로 들어간다. 목록은 아래 [상품 목록 (공통, 확정)](#상품-목록-공통-확정)을 따르고, `분류 확인 전` 상품은 이름 앞에 작은 점을 붙인다.
- `카테고리 미지정` 상품은 홈 조치 영역에 두지 않고 카테고리 목록 맨 아래 `미지정` 묶음에 둔다. 제품 문서도 같은 기준으로 고쳤다.

### 목적 탭 (확정)

디자인 캔버스의 `목적 탭 확정 (PT-A8)` 보드를 기준으로 확정한다.

- 목적마다 색 블록을 하나씩 두고, 블록끼리 겹치지 않게 세로로 쌓는다. 블록은 항상 접힌 상태이며 펼치지 않는다.
- 블록 왼쪽에는 설명(작은 라벨)과 목적 이름, 오른쪽에는 후보 원형 썸네일을 둔다. 썸네일은 최대 3개까지 겹치고 넘치면 `+N`으로 표시한다. 빈 목적은 점선 원으로 표시한다.
- 목적 블록에는 가격 범위를 두지 않는다. 한 목적에 통화가 다른 후보가 섞일 수 있어 범위를 계산할 수 없기 때문이다.
- 블록을 누르면 목적 상세로 넘어간다. 목적 상세는 카테고리 상세(CT-C)와 같은 형태로, `‹ 목적` 뒤로 가기, 두 줄 헤드라인, 라벨과 개수, 공통 상품 목록을 쓴다.
- 목적 색은 사용자가 고르지 않고 앱이 정해진 색에서 차례로 붙인다.
- 상단 전환 버튼으로 `진행 중`과 `아카이브`를 오간다.
- 작은 원형 썸네일은 실제 쇼핑몰 대표 이미지(흰 배경, 룩북, 여백이 큰 사진)로 확인한 결과 원본 비율 그대로 원 안을 채우는 방식을 유지한다.
- 가격은 원래 통화로 표시한다(예: `¥25,000`).
- 아카이브 목록은 `A8-AR2`로 확정한다. PT-A8과 같은 블록을 흰 바탕으로 두고 제목 앞에 원래 목적 색 점을 붙인다. 왼쪽 라벨은 종료 날짜(`9월 20일 종료`)이며, 오른쪽에는 후보 겹침 대신 결과만 둔다. 구매한 경우 구매 상품의 원형 사진에 목적 색 ✓ 배지를, 구매하지 않은 경우 `구매 안 함`을 표시한다.
- 흰 블록으로 진행 중(색 블록)과 끝난 기록을 구분한다. 회색 블록에 흑백 사진을 쓴 안(PT-A7a)은 어색하다는 의견으로 제외했다.
- 아카이브 기록 상세는 `아카이브 상세 확정 (AD-F2)` 보드를 기준으로 한다.
  - 윗부분은 화면 맨 위부터 헤드라인·설명까지 목적 색 면(아래 모서리 32px)을 깐다(AC-1). 이 면 위에는 `‹ 목적` 뒤로 가기와 오른쪽 위 `···` 메뉴, 종료 날짜 라벨, 두 줄 헤드라인(제목 / `○○로 정했어요.` 또는 `구매 없이 비교를 끝냈어요.`)과 제목 수정 버튼.
  - 목록: 목적 상세와 같은 공통 상품 목록 하나로 보여준다. 구매한 상품을 첫 칸에 원래대로 두고 `구매한 상품` 표시를 붙이며, 구매하지 않은 후보는 사진과 정보를 크게 흐리게(사진 불투명도 약 0.3, 글자 30%) 처리한다. 구매 없이 끝낸 기록은 흐리게 하지 않는다.
  - 목록 카드는 공통 규칙대로 이름·가격 한 줄만 둔다. 아카이브 당시의 카테고리 이름은 확인 단계 후보 목록에서 보여준다.
  - `비교 다시 시작하기`(아카이브 취소·전체 복원)와 `기록 지우기`(기록 전체 삭제, 되돌릴 수 없음)는 `···` 메뉴의 바텀 시트에 설명과 함께 둔다.
  - 아카이브 동작은 `아카이브 동작 확정 (떠 있는 카드 시트)` 보드를 기준으로 한다. `···` 메뉴에서 동작을 고르면 확인 단계로 이어지고, 실행 뒤에는 하단 알림으로 결과를 알린다.
  - 메뉴 카드: 기록 제목과 원형 닫기 버튼을 머리 줄에 두고, 동작은 구분선·아이콘 배경 없이 아이콘·제목·설명·›로 보여주며 항목 사이를 넓게(36px) 띄운다. `기록 지우기`는 빨강으로 쓴다.
  - 확인 단계: 카드 두 장으로 나눈다. 위 카드는 원형 뒤로·아이콘·원형 닫기와 가운데 정렬 질문·설명, 아래 카드는 작은 라벨(`진행 중으로 돌아갈 후보` / `함께 사라질 후보`)과 후보 목록(56px 사진, 16px 이름과 구매 표시, 14px 당시 카테고리·가격), 실행 버튼(다시 시작하기는 검정, 기록 지우기는 빨강)이다.
  - 제목 수정 버튼은 `이름과 설명 바꾸기` 카드를 연다. 제목(최대 40자, 비우면 처음 목적 이름으로 복귀)과 설명(선택, 최대 200자)을 함께 고친다. 목적 설명은 헤드라인 아래에 보여준다.

### 목적 상세 동작 (확정)

디자인 캔버스 `확정 화면` 페이지의 `목적 상세 · 동작` 보드를 기준으로 한다(PD-A 흐름).

- 비교 끝내기 버튼은 목록 위에 떠 있는 검은 버튼으로, 화면 폭을 채우지 않고 글자 폭에 맞춰(안쪽 여백 12/16px, 13px 글자) 가운데에 둔다.
- 버튼을 누르면 `구매한 상품이 있나요?`에서 후보 중 하나나 `사지 않았어요`를 고르고, 다음 카드에서 `비교를 끝낼까요?` 확인(구매한 상품, 함께 보관할 후보 수) 후 아카이브에 보관한다.
- 오른쪽 위 `···` 메뉴에는 `이름과 설명 바꾸기`와 `목적 지우기`를 둔다. 목적을 지우면 상품은 남고 후보는 목적 미지정이 된다.
- 시트는 모두 공통 떠 있는 카드 시트를 쓴다.
- 목적 상세에 색을 더 쓰는 안(버튼·목록·면에 목적 색)은 모두 보류했다.

### 상품 목록 (공통, 확정)

카테고리 상세, 목적 상세, 아카이브 기록 상세의 상품 목록은 같은 규칙을 쓴다. 핀터레스트처럼 촘촘한 2열 목록이다.

- 간격: 화면 양옆 6px, 열 사이 4px, 행 사이 10px(390pt 폭에서 카드 폭 187). 사진 모서리는 16px.
- 사진은 **원본 비율 그대로** 보여주고, 각 카드를 더 짧은 열에 넣는 벽돌(masonry) 배치를 쓴다. 비율 범위를 제한하거나 모두 정사각으로 맞춘 안(IR-B, IR-C)과 비교해 택했다. 쇼핑몰 대표 이미지는 정사각이 많아 대부분 가지런하고, 룩북 사진처럼 세로로 긴 사진만 리듬을 준다.
- 사진 아래 글자는 한 줄이다. 왼쪽에 이름(넘치면 이름만 말줄임), 오른쪽에 가격(원래 통화, 줄이지 않음). 판매처·플랫폼 이름은 목록에 두지 않는다.
- 상태 표시(`구매한 상품`, `카테고리 고르기`)는 이름 줄 위에 작게 붙인다.
- 스크롤: 뒤로 가기·헤드라인·라벨과 개수·정렬(`최근 저장순`) 줄까지는 고정하고, 그 아래 목록만 스크롤한다. 비교 끝내기 버튼과 하단 탭은 목록 위에 떠 있다.
- 양옆 6px은 상품 목록과 블록 목록(홈 챙길 일 블록, 목적 블록, 아카이브 블록) 모두에 쓴다. 헤드라인·라벨·뒤로 가기 같은 글자는 기존 여백(20px)을 유지한다. 목록 양옆 16px(카드 177) 안과 비교해 6px을 택했다.

### 바텀 시트 (공통, 확정)

- 바텀 시트는 화면 끝에 붙이지 않고 양옆 12px, 아래 16px 떨어진 떠 있는 카드로 둔다. 네 모서리를 28px로 둥글게 하고 옅은 그림자를 준다.
- 뒤 화면은 어둡게 가리지 않고 밝은 덮개(바탕색 40%)와 약한 흐림(2px)으로 물러나게 한다. Android 12 미만처럼 흐림을 쓸 수 없으면 덮개만 쓴다.
- 닫기는 머리 줄의 원형 X 버튼으로 한다. 여러 단계가 있으면 위 카드(뒤로·아이콘·닫기와 가운데 제목)와 아래 카드(내용과 실행 버튼)로 나눈다.

## 1차 시안 (대체됨)

자체 스타일·라이트 모드, 쿨 화이트 + 인디고 색, IBM Plex Sans KR, 자유 격자, 이미지 위 배지, 바텀 시트 확인창까지 정하고 상품 확인과 편집 화면 8개를 그렸다. 흰 카드·테두리·알약 칩·배지가 모든 화면에 같은 무게로 반복되고 글자 위계가 약해 템플릿 같은 인상이 강했기 때문에 초기화했다. 1차 시안은 디자인 캔버스의 `1차 시안 (초기화)` 페이지에 기록으로 남아 있다.

## 남은 결정

- 색·글꼴·기초 요소 재정리. 목적 상세에서 목적 색을 더 쓰는 안은 보류 중이다.
- 목적 상세 동작의 세부 규칙
  - 비교를 끝낼 때 구매한 상품이나 `사지 않았어요`를 반드시 골라야 하는지
  - 후보가 없는 목적에서 비교 끝내기 버튼을 숨길지, 비활성으로 둘지
  - `구매한 상품 고르기` 시트의 `가격 · 판매처` 줄에서 판매처를 뺄지(목록 카드와 맞추기)
- 핵심 흐름 4개(상품 저장, 구매 후보 정리, 상품 확인과 편집, 구매 결정 종료)의 화면 설계
