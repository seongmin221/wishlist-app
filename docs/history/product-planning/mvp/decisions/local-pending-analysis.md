# 제품 결정: 로컬 대기 저장과 분석 재시도

> 상태: **확정** · 날짜: 2026-09-10 · 영역: **제품·클라이언트·서버**

## 결정

- 시스템 공유 시트에서 앱을 선택하면 URL을 먼저 로컬에 저장하고 공유 시트는 닫힌다.
- 로그인했고 네트워크를 사용할 수 있을 때만 서버에 저장·분석을 요청한다.
- 로그인하지 않았거나 오프라인이면 URL을 로컬 대기 상태로 둔다.
- 로컬 대기 URL은 서버 전송에 성공하거나 사용자가 삭제할 때까지 자동 만료 없이 보관한다. 앱 종료와 기기 재부팅 후에도 유지한다.
- 서버에 전달되기 전에는 해당 기기에만 존재하므로 다른 기기에서 조회할 수 없다. 앱을 삭제하면 로컬 대기 URL도 삭제되며 재설치 후 복구하지 않는다.
- 로그인 뒤에는 대기 항목 전체를 자동으로 분석 요청한다. 항목별 진행 상태로 알리므로 일괄 시작 안내는 제공하지 않는다.
- 비로그인 상태에서 로컬에 저장한 대기 URL은 이후 로그인한 계정의 항목으로 서버에 생성한다.
- 로그인한 상태에서 오프라인으로 저장한 로컬 대기 URL은 저장 당시 계정에 귀속한다. 다른 계정에는 이전·노출하지 않고, 원래 계정으로 다시 로그인했을 때 서버 요청을 재개한다.
- 로그인한 상태에서 서버에 저장·분석 요청한 항목은 그 계정에 귀속한다. 로그아웃 후 다른 계정으로 로그인해도 기존 계정의 분석 작업이나 결과는 새 계정에 이전·노출하지 않는다.
- 앱 실행 중 네트워크가 복구되면 대기 항목을 자동 요청한다. 앱이 꺼져 있어 복구를 감지하지 못한 경우에는 사용자가 UI에서 직접 분석을 요청할 수 있다.
- 서버가 분석을 시도한 뒤 실패하면 항목을 서버에 보존한 `재시도 가능` 상태로 두고, 사용자가 직접 보완하기 전까지 다시 분석을 요청할 수 있게 한다.
- 일부 정보가 누락되거나 추출이 불가능한 경우에는 이를 별도로 표시하고, 원본 링크 열기 및 상품 정보 직접 입력을 제공한다.
- 분석 중인 항목은 수정하거나 재추출할 수 없고 삭제만 할 수 있다.
- 분석 중인 항목을 삭제하면 목록에서 즉시 제거한다. 진행 중인 작업은 가능한 경우 중단하고, 늦게 완료된 결과를 삭제된 항목에 반영하거나 항목을 자동 복원하지 않는다.
- 삭제한 상품과 같은 URL을 다시 공유하면 새로운 항목으로 처리한다.
- 최초 앱 진입에서는 로그인을 요구하지만 건너뛸 수 있다. 비로그인 홈은 로컬 저장 항목, 로그인 필요 안내, 로그인 진입점을 제공한다.

## 이유와 영향

공유로 수신한 URL을 즉시 로컬에 보관하면 로그인 여부나 순간적인 네트워크 단절 때문에 사용자의 저장 의도가 사라지지 않는다. 자동 만료를 두지 않으면 사용자가 다시 로그인하거나 네트워크를 복구하기까지 저장 의도를 유지할 수 있다. 서버 요청 전 실패와 서버 분석 실패를 분리하면 자동 재개 가능한 대기 상태와 사용자가 통제하는 재시도 상태를 명확히 표현할 수 있다.

클라이언트는 로컬 대기 항목과 서버에 생성된 항목을 구분해 보관해야 하며, 로그인·네트워크 변화에 따라 대기 항목을 전송한다. 서버 API는 같은 항목의 재요청에도 안전하게 동작해야 한다. 삭제와 분석 완료가 동시에 발생하더라도 완료 결과가 삭제를 되돌리지 않아야 한다.
