# 제품 결정: B3 목적 API 정책

> 상태: **확정** · 날짜: 2026-10-07 · 영역: **제품·서버·AI**

B3 착수 전 제품 문서에 없던 목적 정책을 사용자가 확인했다. 이 결정은 [AI 목적 자동 연결과 재판단](ai-purpose-linking.md)의 재판단 규칙과 확정 상품의 목적 처리를 일부 대체한다.

## 결정

- 목적 이름은 최대 40, 설명은 최대 200 Unicode code point다. 사용자 category와 같은 문자 규칙을 쓰고 이름 중복을 허용한다.
- ACTIVE 목적은 owner당 최대 30개다. 신규 생성 성공은 owner별 직전 60초 10건이다. 생성 receipt는 계정 데이터가 유지되는 동안 보존한다.
- 목적 만들기의 기본 선택은 색 CORAL, 아이콘 HEART다. 서버는 두 key를 필수로 받는다.
- 최근 활동은 생성 또는 후보 유입(사용자 연결·AI 연결·다른 목적에서 이동)이다. 목적 탭·홈·AI 후보 선정에 같은 순서를 쓴다.
- 후보 수는 해당 목적에 연결된 ACTIVE 상품 전부다. 미리보기는 최근 저장순 4개다.
- AI 근거는 활동순 ACTIVE 목적 최대 10개의 이름·설명과 목적별 최근 후보 상품명 최대 2개다. 토큰 초과 시 목적 근거는 상품명 → 설명 → 이름만 → 5개로 축소 → 제외 순으로 줄어든다. 같은 단계에서 상품 metadata와 사용자 category도 함께 줄어드는 전체 순서는 [B3 설계의 T0~T5 표](../../../../superpowers/specs/2026-10-07-b3-purpose-management-design.md#토큰-단계와-최악-크기)를 따른다.
- **MVP에서는 목적 이름·설명 편집 뒤 미확정 AI 연결을 재판단하지 않는다.** 진행 중 분석이 편집 전 목적을 골랐다면 그 목적 연결만 버린다.
- **확정·보류한 상품의 빈 목적을 AI가 채우지 않는다.** B0/B2의 빈 목적 슬롯 신규 연결 동작을 바꾼다.
- 목적 텍스트에는 사용자 category의 AI 후보 안전 제외를 적용하지 않고 JSON 데이터 분리로 보호한다.
- B3의 archive 입구 요약은 ARCHIVED 목적의 실제 수(현재 0)와 빈 제목 목록이며 B10에서 archive 기록으로 출처를 바꾼다.

## 판단 근거

- 활동순: 생성순만 쓰면 오래된 목적이 AI 후보 10개에서 빠져 자동 연결을 받지 못한다. 사용자는 이를 검토한 뒤 활동순을 유지했다.
- 감수한 부작용: AI 연결도 활동이므로 AI가 자주 고르는 목적은 상위 10개에 남고, 밀려난 목적은 사용자가 직접 연결·이동해야 AI 후보로 돌아온다. 사용자가 이후 AI 연결을 해제해도 이미 올라간 활동 시각은 되돌리지 않는다. ACTIVE 목적이 30개로 제한되어 밀려나는 범위가 제한적이라 이를 감수한다.
- 재판단 없음: 편집할 때마다 완료된 상품을 다시 분석하면 상품 수만큼 AI 비용이 들고 상품이 다시 분석 중이 된다. 제품 원칙은 재판단을 허용할 뿐 요구하지 않으므로 MVP에서는 하지 않는다.
- 확정·보류의 빈 목적 보호: 사용자가 검토를 마친 상품에 검토 없는 AI 목적이 생기면 "확정한 목적은 자동으로 바꾸지 않는다"는 원칙과 어긋난다. 보류 항목을 다시 검토 영역에 올리는 방식은 보류 자동 재노출 금지와 충돌한다.
- 안전 제외 미적용: AI 응답은 실제로 보낸 목적 alias 집합으로만 검증되므로 최악의 결과는 존재하는 다른 목적과의 잘못된 연결이고, 그 결과는 검토 대기로 표시되어 사용자가 분류·목적 확인에서 바로잡는다. 사용자 category는 별도 제품 결정([입력과 AI 안전성](custom-category-safety.md))이 제외를 요구하고 상품의 기본 분류가 되므로 영향이 더 크다. 목적 근거의 상품명은 외부 쇼핑몰 추출 텍스트이며 목적 이름·설명과 같은 JSON 데이터 경계로 보낸다.
- 5개 축소 단계: 추정상 최악 입력에서도 목적 10개의 이름은 2,000 token 안에 남지만, 추정이 틀린 경우 목적 전체가 빠지기 전의 보험으로 둔다.

근거 문서에서 확정된 값: 목적 6색과 기본 코랄([디자인 결정](../../../../design/decisions.md) 2026-10-02), 아이콘 8개(design canvas·handoff 보드), 이름·색·아이콘 필수와 빈 목적 유지([구매 후보 정리](../../../../product/organize-candidates.md)), 빈 목적 archive 불가([구매 결정 종료](../../../../product/finish-a-purchase-decision.md)). 상품 편집 취소 뒤에도 생성한 목적은 빈 목적 자동 삭제 금지 규칙에 따라 남는다.

## 제품·구현 영향

- 제품 기준 문서 [구매 후보 정리](../../../../product/organize-candidates.md)의 목적 만들기·AI 목적 연결 절에 입력 제한·한도·기본 선택·재판단 없음·확정 상품 보호를 반영했다.
- [AI 목적 자동 연결과 재판단](ai-purpose-linking.md)은 일부 대체 상태로 바꿨다.
- 사용자가 확정한 목적 미지정의 저장 표현은 USER 출처 + 목적 없음 하나로 둔다.
- 서버 계약·데이터·AI 단계는 [B3 설계](../../../../superpowers/specs/2026-10-07-b3-purpose-management-design.md)를 따른다.
