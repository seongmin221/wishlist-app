# B3 목적 API 정책 확정

2026-10-07 B3 착수 전 사용자가 제품 문서에 없던 목적 정책을 다음과 같이 확인했다.

- 이름 최대 40, 설명 최대 200 Unicode code point다. 사용자 category와 같은 문자 규칙을 쓰고 이름 중복을 허용한다.
- ACTIVE 목적은 owner당 최대 30개다. 신규 생성 성공은 owner별 직전 60초 10건이다. 생성 receipt는 계정 데이터가 유지되는 동안 보존한다.
- 최근 활동은 생성 또는 후보 유입(사용자 연결·AI 연결·다른 목적에서 이동)이다. 목적 탭·홈·AI 후보 선정에 같은 순서를 쓴다. 생성순만 쓰면 오래된 목적이 AI 후보 10개에서 빠지는 점을 검토한 뒤 활동순을 유지했다.
- AI 근거는 활동순 ACTIVE 목적 최대 10개의 이름·설명과 목적별 최근 후보 상품명 최대 2개다. 토큰 초과 시 상품명 → 설명 → 이름만 → 사용자 category 제외 → 목적 제외(공용 최소) 순으로 축약한다.
- 목적 이름·설명 편집 뒤 미확정 AI 연결을 재판단하지 않는다. 진행 중 분석이 편집 전 목적을 골랐다면 그 목적 연결만 버린다.
- 확정·보류한 상품의 빈 목적을 AI가 채우지 않는다. B0/B2의 빈 목적 슬롯 신규 연결 동작을 바꾼다.
- 후보 수는 해당 목적에 연결된 ACTIVE 상품 전부다. 미리보기는 최근 저장순 4개다.
- 목적 만들기의 기본 선택은 색 CORAL, 아이콘 HEART다. 서버는 두 key를 필수로 받는다.
- 목적 텍스트에는 사용자 category의 AI 후보 안전 제외를 적용하지 않고 JSON 데이터 분리로 보호한다.
- B3의 archive 입구 요약은 ARCHIVED 목적의 실제 수(현재 0)와 빈 제목 목록이며 B10에서 archive 기록으로 출처를 바꾼다.

근거 문서에서 확정된 값: 목적 6색과 기본 코랄(design decisions 2026-10-02), 아이콘 8개(design canvas·handoff 보드), 이름·색·아이콘 필수와 빈 목적 유지([구매 후보 정리](../../../../product/organize-candidates.md)), 빈 목적 archive 불가([구매 결정 종료](../../../../product/finish-a-purchase-decision.md)). 상품 편집 취소 뒤에도 생성한 목적은 빈 목적 자동 삭제 금지 규칙에 따라 남는다.

구체적인 계약은 [B3 설계](../../../../superpowers/specs/2026-10-07-b3-purpose-management-design.md)를 따른다.
