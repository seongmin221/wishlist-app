# 제품 결정: B4 상품 목록과 홈 조회

> 상태: **제품 정책 확정 · 설계 spec 승인** · 날짜: 2026-10-07 · 영역: **제품·서버**

제품 문서와 B1~B3 계약을 대조해 B4의 제품 정책을 확정했다. 이 문서는 제품 결정을 기록하며 구현 완료를 의미하지 않는다. 설계 승인과 실행 상태는 연결된 spec·계획·구현 이력에서 관리한다.

## 결정 — 사용자 확인 완료

- 홈 최근 목적은 ACTIVE 목적 최대 3개이며 빈 목적도 포함한다. B3의 `activityAt DESC, id DESC`를 유지한다.
- 목적 요약 카드는 이름·색·아이콘·후보 수·최근 활동 시각·**최근 저장 후보 최대 4개**를 제공한다. 후보별 이미지는 없으면 null이며 클라이언트가 placeholder를 표시한다. 이미지가 null인 후보도 4개 한도에 포함하고, 이미지가 있는 후보만 골라 채우지 않는다. 빈 목적은 후보 수 0과 빈 미리보기로 표시한다.
- 연속 처리 화면이 살아 있으면 현재 카드의 anchor로 재조회한다. 앱 신규 실행은 최신 첫 페이지부터 시작한다.
- ‘처음부터 다시 보기’는 기기의 건너뛴 기록을 초기화하고 현재 미완료 대상을 처음부터 재조회한다. 기존 GET을 재사용하며 별도 restart 서버 API를 만들지 않는다.
- ‘다시 보기’나 재진입을 이유로 상품의 `reviewStatus=CONFIRMED`를 PENDING으로 되돌려 검토 대상으로 올리지 않는다. `DEFERRED`도 분류 검토 영역에 자동 재노출하지 않는다. 이 규칙은 상품의 검토 상태에 관한 것으로, 끝난 연속 처리 화면을 다시 열어 현재 미완료 상품을 조회하는 것을 금지하지 않는다.
- 목적 미지정 filter는 `purposeId == null`인 ACTIVE 상품 전부다. UNASSIGNED와 USER+null을 모두 포함하며 분석 중·보완 필요도 포함한다. 응답의 source 구분은 유지한다.
- ITEM-02의 category 조회는 공용 세부 C-ID 또는 custom UUID인 `categoryId`만 지원한다. B4에서 parentId 조회는 추가하지 않는다.
- 일반 categoryId 목록은 같은 owner·ACTIVE·categoryId 일치 상품 중 **비어 있지 않은 제품명**이 있는 상품을 표시한다. categoryId 일치는 필터 조건이며, 추가로 걸러내는 표시 조건은 제품명 존재다. 분석 상태와 review는 제한하지 않으며 PROCESSING도 제품명이 있으면 포함한다. 목적별·목적 미지정 목록에는 제품명 조건을 적용하지 않는다.
- 이름 누락은 기존 WishlistItemPolicy의 `isNullOrBlank()` 기준이다. null·빈 문자열·공백만 있는 이름은 누락으로 보며, 일반 공백뿐 아니라 탭·줄바꿈만 있는 이름도 제외한다. 저장된 이름 원문을 수정하는 규칙은 아니다.

## 추가 결정 — 사용자 확인 완료

### 1. category count는 목록 표시 집합과 일치

**결정: A안 채택.** CAT-01/02의 category itemCount를 ITEM-02 일반 category 목록의 표시 집합과 맞춘다. 현재 count는 해당 category의 ACTIVE 전체이고 목록은 그중 비어 있지 않은 제품명이 있는 상품만 표시한다. 따라서 이름이 없는 상품 3개만 연결돼 있으면 count=3인데 목록은 비어 있다. 공용 category는 BROWSE에서 itemCount>0일 때 노출되므로 실제로 빈 목록으로 연결되는 category가 보일 수 있다.

- **A안 — 목록 표시 기준에 맞춤(권장):** 이름이 있는 목록 상품만 itemCount에 포함하여 카드의 숫자와 실제 목록을 일치시킨다. 공용 category의 BROWSE 노출도 이 기준을 따른다.
- **B안 — 현재 ACTIVE 전체 count 유지:** 기존 B2 집계는 유지되지만 이름이 없는 상품 때문에 count가 양수인 공용 category에서 빈 목록으로 연결될 수 있다.

A안은 사용자에게 보이는 빈 목록 불일치를 해소하므로 권장한다. 기존 B2의 ACTIVE 전체 집계를 변경한다. 공용 category 노출·상위 합계·테스트 기대값도 같은 표시 집합으로 맞춘다. custom 개수 한도는 상품 집계와 무관하므로 유지한다.

### 2. 서버 할 일 합계 필드는 제공하지 않음

HOME-01 inventory에는 서버 할 일 수가 제안돼 있지만, [디자인 결정](../../../../design/decisions.md)과 현재 홈 제품 문서에는 합계를 보여 주는 배지나 상단 문구의 위치가 명시돼 있지 않다. **결정: C안 채택.** HOME-01은 그룹별 count만 제공하고 별도 서버 할 일 합계 필드를 두지 않는다. 검토한 대안은 다음과 같다.

- **A안 — 분석 중 포함:** 분석 중·정보 보완·분류 검토를 합산해 서버의 할 일 카드 전체 건수를 제공한다.
- **B안 — 분석 중 제외:** 정보 보완·분류 검토만 합산해 사용자가 연속 처리로 직접 해결할 건수를 제공한다.
- **C안 — 합계 필드 없음(권장):** 그룹별 count만 반환하며 합계의 표시 위치와 의미가 정해질 때 필드를 추가한다. 합계가 필요하면 클라이언트가 그룹 count를 계산할 수 있고, 로컬 pending 합성도 같은 곳에서 처리한다.

판단 근거: 디자인 결정의 2026-10-03 행은 분류 중도 할 일 카드로 다루지만 연결된 처리 화면 없이 접기·펼치기를 제공한다. 원본 보기·삭제 같은 상품 행동과 직접 보완·검토할 작업은 구분할 수 있다. 분석 중 영역의 표시와 개별 count는 기존 정책대로 유지하며 로컬 pending은 어떤 서버 그룹 count에도 넣지 않는다.

## 판단 근거

결정 항목은 사용자 선택이며, 아래는 기존 제품 원칙과 구현 관점의 근거다.

- **빈 목적도 홈 최근 목적에 포함:** B3는 생성도 활동으로 보고 빈 목적을 유지한다. 홈에서도 같은 활동순을 사용하면 새로 만든 빈 목적으로 바로 들어갈 수 있고, 목적 탭과 홈에서 최근 목적의 의미가 달라지지 않는다. 최대 3개는 제시한 2개/3개 선택지 중 사용자가 고른 값이다.
- **PROCESSING도 최소 정보가 있으면 일반 목록에 포함:** 기존 제품 원칙은 제품명과 category를 목록 사용 조건으로 삼고 추출 상태나 검토를 추가 관문으로 두지 않는다. 재처리 중에도 이 정보가 남아 있다면 목록에서 계속 접근할 수 있다. 상태별 편집·재분석 가능 여부는 allowedActions로 구분한다.
- **B4에서 parentId 조회를 추가하지 않음:** W09와 ITEM-02 inventory의 category 조회는 세부 categoryId를 기준으로 한다. 현재 요구를 충족하고 조회 범위를 유지하기 위해 상위 category 통합 조회 선택지 대신 세부 조회를 선택했다.
- **restart는 현재 미완료 대상 재조회:** 건너뛰기는 기기 session 상태이고 확정·보류는 상품의 서버 상태다. 기기 skip만 초기화하면 미완료 대상을 다시 볼 수 있으며, 완료한 상품 상태를 되돌리는 새 명령이 필요하지 않다.
- **화면 생존 중 anchor 복구·신규 실행은 최신 첫 구간:** 목록 앞 삽입·삭제와 가변 카드 높이 때문에 항목 번호나 절대 scroll offset으로는 위치를 유지할 수 없다. 살아 있는 화면의 stable item과 내부 offset을 복구하고, 프로세스 신규 실행에는 viewport를 영구 복원하지 않는 기존 계약을 따른다([위치 유지 근거](../../../../architecture/wishlist-item-state-api.md#항목-번호-또는-절대-scroll-offset-복원)).
- **목적 미지정은 null인 ACTIVE 전부:** 특정 purposeId 목록과 같은 목적 축으로 다루어 분석·보완 상태 때문에 미연결 상품이 빠지지 않게 한다. UNASSIGNED와 USER+null의 의미 차이는 source로 보존한다.

## 제품·구현 영향

- 결정의 영향: HOME-02 anchor 계약 보완 필요([문서·코드 대조](../../../architecture/server/b4-read-api-implementation-2026-10-07.md#문서코드-대조)).
- CAT-01/02 표시용 count·공용 BROWSE 노출·상위 합계와 ITEM-02에 공통 visibility predicate를 적용한다. B8 삭제 영향은 이름 누락을 포함한 ACTIVE 전체 집합이며 표시용 count를 재사용하지 않는다. 기존 B2 테스트 기대값 변경의 근거는 이 결정이며 구현 이력에도 남긴다.
- HOME-01은 분석 중·정보 보완·분류 검토의 개별 count를 반환한다. 합계 표시가 필요하면 클라이언트가 의미에 맞는 그룹들을 합산한다.
- 목적별·목적 미지정 목록은 제품명이 없는 상품도 반환한다. 클라이언트는 이 카드에 이름 누락을 나타내는 대체 제목을 표시해야 한다. 구체적인 문구는 클라이언트 표시 계약에서 정하며, 서버가 임의의 제품명을 저장하거나 응답값으로 만들어 넣지는 않는다.
