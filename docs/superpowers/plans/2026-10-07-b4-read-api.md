# B4 상품 목록·홈 조회 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ITEM-02 → HOME-02 → HOME-01을 구현해 홈·연속 처리·일반 목록의 대상과 건수를 일치시키고 현재 카드 주변을 복구한다.

**Architecture:** 기존 JDBC/Ktor 구조에 공통 조회 predicate·keyset repository와 read service를 추가한다. 기존 상품 mapper와 PurposeRepository를 재사용하며 요청당 짧은 readOnly repeatable-read snapshot에서 count·window·preview를 읽는다. requiredAction 저장 컬럼과 cursor 서명은 추가하지 않는다.

**Tech Stack:** Kotlin 2.3.21/JDK 17, Ktor 3.6.0, PostgreSQL 16, Flyway, kotlinx.serialization, Testcontainers. dependency 변경 없음.

**Spec:** [승인된 B4 조회 설계](../specs/2026-10-07-b4-read-api-design.md). [제품 결정](../../history/product-planning/mvp/decisions/b4-read-api-policy-2026-10-07.md), [baseline](../../history/architecture/server/b4-read-api-implementation-2026-10-07.md#수신과-baseline).

> 상태: 계획 승인·Native 실행 중. 완료한 항목만 checkbox로 표시한다.

## Global Constraints

- 서버·docs만 변경한다. client/·design/handoff/·다른 worktree·V1~V14 파일은 수정하지 않는다. 로컬 커밋까지 진행하며 push·PR·merge·rebase·force push는 하지 않는다.
- 모든 SQL에 인증 owner와 ACTIVE/scope를 강제한다. 최근 저장순 `(created_at DESC,id DESC)`이며 clientCreatedAt은 정렬하지 않는다.
- categoryId는 공용 leaf C-ID/custom UUID만 지원한다. category visibility와 CAT-01/02 표시 count는 비공백 제품명 조건을 공유한다. B8 삭제 영향은 이름 누락을 포함한 ACTIVE 전체이며 표시용 count를 재사용하지 않는다.
- purposeId는 해당 목적의 ACTIVE 전체 후보, purposeUnassigned=true는 purpose_id IS NULL의 ACTIVE 전체다. 이름·category·analysis/review를 추가 제한하지 않는다.
- ITEM 페이지 기본 40, HOME 기본 20, limit 1~100. 단일 anchor query, before/after 각각 기본 20·0~20, 기준 상품 포함 최대 41개. page와 anchor 입력은 혼용하지 않는다.
- anchor 삭제/이동/처리 뒤에는 다음(더 오래된) 항목, 없으면 바로 앞 항목으로 복구한다. requestedAnchorItemId 유지, 대체 항목 중심 window, anchorResolved=false는 정상 결과다.
- 홈 정보 보완 group은 INFORMATION_COMPLETION/CATEGORY_ASSIGNMENT/CATEGORY_REASSIGNMENT를 합친다. action query·restart mutation은 추가하지 않는다. CONFIRMED/DEFERRED를 검토 대상으로 되돌리지 않는다.
- 홈 group preview 최대 4개, 최근 ACTIVE 목적 최대 3개·빈 목적 포함·activity_at DESC/id DESC, 목적 preview 최근 저장 후보 최대 4개·null 이미지 포함. 별도 할 일 합계와 로컬 pending count는 없다.
- B1~B3 상품 DTO·allowedActions·purpose source 의미를 유지한다. brand/price/currency/merchant/metadataCheckedAt은 B4 nullable이고 실제 추출/저장은 B5다.
- cursor는 B3 방식의 Base64URL·owner digest·scope·endpoint·용도·timestamp/UUID 범위 검증이다. 최대 2048 ASCII 문자, epoch microseconds 0~253402300799999999. HMAC·secret·RuntimeConfig 변경 없음. 구조가 유효한 자기 범위 위치 조작을 탐지한다고 주장하지 않는다.
- 조회는 잠금 없이 repeatable-read, mutation의 owner→purpose→item→job 순서는 유지한다. purpose row hard delete 없음. 상품 mutation·Scheduler/browser·archive는 구현하지 않는다.
- 의미별 커밋은 `docs`/`feature(server)`/`bugfix` + 한글 제목·빈 줄·간결한 한글 본문. 관련 issue 없음. author/committer는 seongmin221로 확인하며 개인정보를 프로젝트 문서에 기록하지 않는다.

## Review Focus

- UUID의 Java signed 비교와 PostgreSQL UUID 정렬이 다르면 동일 시각에서 페이지가 누락될 수 있다. DB 정렬을 기준으로 7fff/8000 경계 id도 앞뒤 왕복한다(Task 3).
- 살아 있는 anchor에 새 항목이 앞쪽에 삽입되거나 방금 처리한 카드가 빠져도 요청 위치가 유지돼야 한다. 전후 boundary cursor와 before/after=0도 검증한다(Task 3/6).
- group count와 카드 사이에 Worker commit이 일어나도 한 응답은 같은 snapshot이어야 한다. 타이밍 sleep 없이 connection proxy/latch로 중간 commit을 만든다(Task 7).
- 이름 없는 custom 상품은 표시 count=0이어도 삭제 영향이 있는 상품이다. 표시 집계가 ACTIVE 전체 집계 의미로 재사용되지 않게 경계를 검증한다(Task 4).
- NONE이 대부분인 큰 owner와 작은 조치 집합에서 정렬 index가 group index처럼 보이지 않아야 한다. 조회 결과 정확성과 스캔 비용을 함께 기록한다(Task 8).
