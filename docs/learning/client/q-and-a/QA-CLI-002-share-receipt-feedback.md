# QA-CLI-002: 공유 직후 저장 확인 카드와 그 한계

> 상태: **학습 Q&A** · 날짜: 2026-10-02

## 질문

시스템 공유 시트로 상품 링크를 공유했을 때, 원래 보던 앱 위에 "저장했어요" 같은 확인 카드를 띄우고 그 안에서 앱 열기·로그인 같은 버튼을 제공할 수 있는가? iOS와 Android 모두 가능한가?

## 짧은 답변

- **확인 카드 자체는 두 플랫폼 모두 가능하다.** iOS는 Share Extension이 기본 작성 시트 대신 직접 만든 화면을 원래 앱 위에 모달로 띄우고, 저장 뒤 스스로 닫을 수 있다. 엄밀히는 공유 시트가 닫힌 *뒤*의 알림이 아니라 확장 화면이 잠깐 보였다 닫히는 것이며, 모달의 표시 방식은 시스템이 정하므로 카드 모양의 자유도는 구현 때 확인이 필요하다. Android는 `ACTION_SEND`를 받는 Activity를 투명·다이얼로그 테마로 만들어 원래 앱 위에 카드를 그리고 `finish()`로 닫는다.
- **iOS Share Extension에서는 본 앱을 여는 공식 방법이 없다.** `extensionContext.open`은 위젯 등 일부 확장에서만 동작하고 공유 확장에서는 지원되지 않는다. 우회 방법은 비공식이라 심사 위험이 있으므로 카드에 "앱에서 보기", "로그인" 같은 버튼을 두지 않는다. Android는 가능하지만 두 플랫폼을 같은 모양으로 맞춘다.
- **앱이 꺼진 상태에서 네트워크 복구를 감지해 자동 전송하는 것은 iOS에서 보장할 수 없다.** 그래서 오프라인 저장 문구는 "다음에 앱을 열면 보내요"로 쓴다. 이는 제품 규칙(앱 실행 중 복구 시 자동 전송, 그 밖에는 다음 실행 또는 사용자 요청)과도 맞다.

## 이 프로젝트의 결정

카드는 저장 확인과 상태 한 줄만 두고 버튼 없이 1~2초 뒤 자동으로 닫는다. 로그인 상태에서 "정보를 가져오는 중이에요"라고 쓰려면 확장이 공유된 로그인 토큰으로 직접 서버에 저장 요청을 보내야 한다. 확장이 로컬 저장만 하고 전송을 앱에 맡길지는 아직 정하지 않았다.

2026-10-07 C3에서 결정했다([ADR-030](../../../history/architecture/client/ADR-030-share-receipt-mode.md)): iOS 확장은 app group inbox에 기록만 하고 앱이 전송한다(직접 전송 자리는 인증 연결 단계에서 켬). iOS 로그인 상태 문구는 "앱을 열면 정보를 가져와요"다. 후속 질문은 [QA-CLI-012](QA-CLI-012-ios-share-starts-analysis.md).
