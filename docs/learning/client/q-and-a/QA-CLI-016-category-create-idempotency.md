# QA-CLI-016: 카테고리 만들기 응답을 잃으면 다시 눌러도 하나만 생기는가?

> 확인 날짜: 2026-10-14 · C5 Task 8 · 구현: [KMP 카테고리](../../../architecture/client/kmp.md#카테고리목록-c5) `CategoryFormPresenter` · 계약: [CAT-03 생성과 replay](../../../architecture/server/category-management-api.md#cat-03-생성과-replay)

**질문:** 만들기를 눌렀는데 연결이 끊겨 응답이 오지 않았다. 서버는 이미 만들었을 수도 있다. 다시 누르면 같은 카테고리가 두 개 생기지 않는가?

**답변:** CAT-03은 `Idempotency-Key`(UUID)를 받는다. 같은 owner가 같은 key와 같은 payload로 다시 보내면 서버는 새로 만들지 않고 처음 만든 카테고리를 돌려준다(replay, 200). 같은 key에 다른 payload는 409 `IDEMPOTENCY_KEY_REUSED`다. 그래서 클라이언트는 제출할 때 key와 **보낸 payload**를 함께 보관한다.

- 다음 제출의 payload가 보관한 것과 같으면 같은 key를 쓴다. 서버가 이미 만들었다면 replay로 같은 카테고리를 받고, 아니면 처음처럼 만든다. 어느 쪽이든 하나다.
- 입력을 바꾼 뒤 제출하면 새 key다. 바뀐 payload에 옛 key를 쓰면 409가 나기 때문이다. 이때 첫 시도가 실제로 성공했다면 카테고리가 하나 더 생길 수 있다(이름이 같으면 중복 409로 막힌다). 알려진 한계로 둔다.
- 서버는 실패한 요청(409·422·429)의 receipt를 남기지 않는다. 그래서 **확실한 거절**을 받으면 보관한 key를 지운다. key를 이어 쓰는 것은 결과를 모르는 실패(연결 끊김·시간 초과·서버 오류)뒤뿐이다.
- 서버는 replay를 20개 한도·60초 5건 검사보다 먼저 처리한다. 폼의 한도 미리 막기도 같은 payload 재전송을 막으면 안 되는데, 한 폼의 사용 개수는 폼을 열 때 받은 값이고 확실한 한도 거절에서만 바뀌므로(그때는 보관한 payload도 지움) 재전송이 막히는 경우는 생기지 않는다.

편집(CAT-04)은 key가 없고 `expectedVersion`으로 같은 효과를 낸다. 응답을 잃은 저장을 다시 보내면 version이 이미 올라 409가 나고, 최신 상세가 내가 보낸 값과 같으면 저장된 것으로 끝낸다.
