# QA-AI-008: 입력 상한을 올리면 목적 근거 축소 문제가 해결되는가

> 2026-10-07 · B3 목적 AI 후보 설계 중 질문

## 질문

목적 근거(이름·설명·후보 상품명)를 넣으면 보통 입력도 2,000 token을 넘는다. 입력 상한을 3,000이나 2,500으로 올리면 해결되는가? 무엇을 먼저 줄여야 하는가?

## 답

**상한을 올리면 완화되지만 축소 단계는 계속 필요하다.**
- 보수적 추정(한글 1자=1 token, ASCII 2.5자=1 token, 공용 taxonomy·지시문 고정분 ≈947)으로 보통 입력의 첫 단계는 약 2,750 token이다. 보통 입력은 상품 300자·custom 3개·목적 10개·설명 30자·상품명 20자로 잡았다.
- 2,500 상한에서는 목적이 10개면 상품명이 빠지고(약 2,290), 목적이 5개 안팎이면 상품명까지 전달된다(약 2,229).
- 최악 입력(custom 20개·목적 10개·모든 입력 최대 길이)은 어느 현실적인 상한도 넘으므로, 마지막에는 공용 taxonomy만 남는 단계가 있어야 한다.
- 실제 값은 운영 중 token-count 응답으로만 알 수 있다.

**비용은 예약 상한에 비례한다.**
- 예산 예약은 호출당 최대 입력·출력 비용으로 잡는다. 2,000/80은 496, 2,500/80은 596 micro USD다.
- 같은 일·월 한도면 처리 가능한 분석 수가 약 17% 줄어든다. B3는 한도를 같은 비율로 올려(일 $0.721·월 $7.21) 처리 건수를 유지했다.
- 원화 hard cap은 보수 환율 1 USD=1,600원 기준 일 약 1,160원·월 약 11,600원이 된다. 이전 월 10,000원 결정을 갱신한 것이다.

**목적 근거를 먼저 줄인다.**
- 사용자 category 설명·예시를 목적과 같은 단계에서 줄이면, B2에서 전달되던 분류 근거가 목적이 생겼다는 이유만으로 빠진다.
- 상품의 기본 분류는 READY 조건이지만 목적은 선택이다. 그래서 목적의 상품명 → 설명 → 5개로 축소 순서로 먼저 줄이고, custom 단계는 B2 순서를 그대로 둔다.
- 대가로 목적 설명이 일찍 빠질 수 있다. 단계는 8개지만 앞 3단계를 순서대로 보고 나머지를 이분 탐색해, 흔한 경우 token-count를 1~3회로 유지하고 최대 6회로 제한한다.
