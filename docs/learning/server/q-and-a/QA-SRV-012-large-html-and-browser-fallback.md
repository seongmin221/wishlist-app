# QA-SRV-012: 큰 상품 HTML과 브라우저 fallback은 어떻게 다뤄야 하나?

## 질문

512 KiB를 넘는 상품 페이지나 연결이 불안정한 사이트는 모두 브라우저 Worker로 보내야 하나?

## 답변

그렇지 않다. Mizuno·8Division의 실제 HTML은 각각 약 783·673 KB였지만, 상품 JSON-LD/OpenGraph 제목이 첫 512 KiB 안에 있었다. 응답 전체를 버리면 추출에 실패하지만, 다운로드·파싱 범위를 512 KiB로 유지한 채 앞부분을 사용하면 상품을 분류할 수 있다. 단, 잘린 HTML에서 쇼핑몰의 일반 `<title>`만 보일 때는 상품명이라고 단정하지 않는다.

KREAM 3건은 다른 종류의 문제였다. 일반 HTTP가 시간 초과되고 브라우저도 한 차례 HTTP 500·빈 문서를 받았다. 브라우저가 네트워크 장애나 사이트의 일시적인 응답 실패를 자동 해결하지는 않는다. 이후 같은 환경의 전체 재실행 세 차례에서 정상 페이지가 돌아와 8건 모두 통과했다. 따라서 실패 원인을 본문 크기·메타데이터 부족·네트워크/사이트 응답으로 나눠 관측하고, 일시적인 실패는 제한된 재시도와 수동 보완 경로를 갖춰야 한다.
