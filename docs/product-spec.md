# 제품 기능 및 스펙

> 상태: **제안** · 최종 갱신: 2026-08-29

## 제품 목적

Safari, Chrome 등에서 발견한 상품 URL을 OS 공유 기능으로 빠르게 저장하고, 서버가 상품 정보를 보강해 개인 위시리스트로 보여주는 native 모바일 앱이다.

## 핵심 사용자 흐름

1. 사용자가 브라우저 또는 지원 앱에서 상품 URL을 공유한다.
2. iOS Share Extension 또는 Android Share Receiver가 URL을 수신한다.
3. 앱은 URL을 우선 저장 요청하고, 항목을 `PROCESSING` 상태로 목록에 즉시 표시한다.
4. 서버 Worker가 URL을 분석해 상품 메타데이터와 AI 상품 유형을 채우고, 사용자의 목적 그룹에 대한 목적 후보를 제안한다.
5. 항목은 추출 결과에 따라 완료, 일부 정보 누락 또는 실패 상태가 된다. 어느 상태에서나 원본 링크를 웹뷰로 열 수 있다.
6. AI는 상품 taxonomy 안에서 상품 유형을 자동 분류한다. 사용자가 만든 목적 그룹이 있으면 목적 후보도 제안할 수 있다. 사용자는 필요할 때 상품 유형과 목적을 변경하며, 사용자 선택은 AI 결과보다 우선한다.

## MVP 범위

### 포함

- 로그인한 사용자별 위시리스트
- URL 공유를 통한 상품 저장
- URL 정규화 및 중복 상품 탐색
- 비동기 상품 메타데이터 추출
  - 제목, 대표 이미지, merchant/domain, 가능한 경우 가격과 통화
  - 가능한 경우 brand와 구조화 metadata
- 미리 정의된 상품 taxonomy에서의 AI 상품 유형 분류
- 사용자가 만든 목적별 비교 그룹
- 사용자 목적 그룹을 바탕으로 한 AI 목적 후보 제안과 간단한 확인
- 상품 유형과 목적의 수동 수정
- 추출 실패·누락 시 제품명과 대표 이미지를 직접 입력·수정
- 사진 보관함에서 대표 이미지 선택
- 처리 상태와 상품 유형·목적별 기본 목록 조회
- 항목 삭제
- 사용자가 선택한 비교 후보 중 구매한 상품을 지정하고, 해당 후보를 일괄 아카이브
- 아카이브 묶음 제목 수정

### 제외

- 가격 변동 알림
- 품절/재입고 감지
- 추출 작업 재시도
- 전문 검색, 유사 상품, 개인화 추천
- 자체 ML 모델 학습·호스팅, GPU 운영
- embedding/vector DB/RAG
- 모든 쇼핑몰의 JS 렌더링·bot protection 우회 지원
- 공유용 웹페이지

## 기능 규칙

- URL 저장 요청은 상품 분석이 끝날 때까지 기다리지 않는다.
- 같은 canonical URL은 하나의 공용 `Product`를 가리킬 수 있고, 각 사용자의 저장 행위는 별도 `WishlistItem`이다.
- 사용자가 공유한 원본 URL은 tracking parameter 등을 포함할 수 있으므로 공용 Product 데이터로 무분별하게 공유하지 않는다.
- AI는 새 상품 유형이나 목적을 임의로 만들지 않는다. 상품 유형은 사전 정의 taxonomy의 ID만 선택하고, 목적은 사용자가 만든 목적 그룹 중에서만 후보를 제안한다.
- 상품 유형 AI 분류 결과는 저장 흐름에서 별도의 사용자 확인을 요구하지 않는다. 사용자는 목록 또는 상품 편집 화면에서 언제든 상품 유형을 변경할 수 있다.
- 상품을 공유해 추가하면 AI가 목적을 유추하고, 항목의 목적 점검 상태를 `NEW`로 둔다. 사용자가 점검하기 전에는 목적별 비교 목록에 바로 표시하지 않는다.
- 현재 사용자가 만든 목적 그룹 중 AI 신뢰도가 가장 높은 값을 임시 목적값으로 사용한다. 적절한 후보를 찾지 못하면 목적 없이 둔다.
- `NEW` 점검 화면에서는 AI가 유추한 목적을 보여주며, 사용자는 목적을 수정·추가·삭제할 수 있다.
- 사용자가 오른쪽으로 스와이프하면 점검 화면의 현재 목적값을 저장하고 목적 점검 상태를 `CONFIRMED`로 바꾼다.
- 사용자가 왼쪽으로 스와이프하면 점검을 스킵하고 AI가 최초 유추한 목적을 적용한 뒤 목적 점검 상태를 `UNCONFIRMED`로 바꾼다.
- `UNCONFIRMED` 항목은 일반 목록에 표시하되 상품 카드에 레드닷이나 뱃지 등으로 미확정 상태를 알려준다.
- 사용자는 목적 후보를 수락하거나, 다른 목적을 선택·추가하거나, 목적 없이 둘 수 있다. 사용자의 선택은 AI 결과보다 우선한다.
- 상품 유형과 목적 그룹은 구매 후보를 비교하는 목록의 그룹 기준이며, 항목의 저장 시점도 함께 보관한다.
- 각 그룹 안의 활성 항목은 최근 저장순으로 표시한다. MVP에서는 다른 정렬 기준을 제공하지 않는다.
- 추출된 가격은 비교를 위한 참고 정보이며, 원래 금액·통화와 마지막 확인 시점을 함께 표시한다. 가격을 실시간 정보로 보장하지 않는다.
- 가격의 통화는 ISO 4217 통화 코드와 함께 보관하며, 항목마다 원래 통화로 표시한다. 서로 다른 통화의 환율 환산은 MVP 범위에 포함하지 않는다.
- MVP의 상품 분류 체계는 상품 taxonomy로 유지한다. 목적은 사용자가 직접 만들고 관리하는 별도 비교 그룹이다.
- 상품은 상품 유형 하나와 목적 최대 하나로 관리한다. 목적은 필수가 아니며 목적이 없을 수 있다.
- MVP에서 비교 후보는 상품 유형 또는 목적 그룹 목록에서 사용자가 직접 선택한다.
- 처리 상태와 무관하게 사용자가 공유한 원본 링크를 웹뷰로 열 수 있다.
- 추출이 실패했거나 제품명·대표 이미지가 누락된 항목은 사용자가 해당 정보를 직접 추가하거나 수정할 수 있다.
- deterministic parser 결과가 충분하면 AI는 추출 대체 수단이 아니라 분류·정규화 보조 수단으로 쓴다.

## 목록과 상태 표현

- 앱의 기본 진입 화면은 카테고리별 구매 후보를 살펴보기 전, 사용자의 조치가 필요한 항목을 한눈에 확인하는 요약 화면이다.
- 진입 화면 상단에는 `분류 중`과 `정보 보완 필요` 영역을 둔다. 이 영역은 각각 처리 중인 항목과 카테고리·제품 정보 보완이 필요한 항목을 보여준다.
- `PROCESSING` 항목은 원본 링크, 로딩 인디케이터, `상품 정보 추출 중` 문구를 표시한다.
- 정보가 완성된 항목은 해당 상품 유형 또는 확인된 목적 그룹의 일반 상품 카드로 표시한다. 내부의 `READY` 상태를 별도 화면 상태로 강조하지 않는다.
- `PARTIAL` 항목은 상품 유형이 정해졌다면 해당 목록에 표시할 수 있으며, 누락된 제품명·대표 이미지를 추가하는 행동을 제공한다.
- `FAILED`, 상품 유형을 정할 수 없는 항목 또는 목적 확인이 필요한 항목은 `정보 보완 필요` 또는 `목적 확인 필요` 영역에 표시한다. 실패 사실 또는 확인 필요 상태를 알리고, 원본 링크 열기와 필요한 정보 직접 입력·선택을 제공한다.
- 사용자가 상품 유형을 정하면 해당 항목은 즉시 그 상품 유형의 비교 목록에 표시된다.
- 사용자가 목적 점검을 오른쪽 또는 왼쪽 스와이프로 처리하면 해당 항목은 확정 또는 미확정 상태로 일반 목록에 표시된다.

## 목적별 비교 그룹

- 목적 그룹은 사용자가 이름을 정해 만든다. 예: `여름 휴가 준비`, `새 책상 꾸미기`.
- 목적 그룹은 이름을 필수로 하며, 설명과 아이콘은 선택적으로 입력할 수 있다.
- 사용자는 목적 그룹을 여러 개 만들 수 있지만, 상품 하나에는 목적을 최대 하나만 연결한다.
- 목적 그룹은 상품 taxonomy와 별개다.
- 앱 진입 시 `NEW` 항목이 있으면 목적 점검 프로세스를 제공한다. 점검을 마치기 전에는 항목을 목적별 목록에 바로 섞지 않는다.
- 목적 확인은 상품 정보 편집 화면과 분리된 짧은 검토 흐름으로 제공한다. 카드 하단에 AI가 제안한 목적을 표시한다.
- 제안 목적을 클릭하면 기존 목적을 선택하거나, 새 목적을 추가하거나, 목적을 삭제해 목적 없음으로 바꿀 수 있어야 한다.
- 오른쪽 스와이프는 현재 화면의 목적값을 확정한다. 그대로 두었다면 AI 목적을, 수정·추가·삭제했다면 변경된 값을 확정한다.
- 왼쪽 스와이프는 화면에서 목적을 어떻게 편집했는지와 관계없이 점검을 스킵하고, AI가 최초 유추한 목적을 미확정 상태로 적용한다.
- 여러 항목이 쌓인 경우 개별 편집 화면을 반복해서 열지 않고 연속 또는 일괄 처리할 수 있어야 한다.

## 상품 정보 편집

- 직접 보완과 추출 완료 후의 수정은 동일한 상품 정보 편집 화면에서 수행한다.
- 편집 화면에서는 제품명, 대표 이미지, 상품 유형, 목적을 한 번에 입력하거나 수정할 수 있으며, 원본 링크를 열 수 있다. 목적은 비워둘 수 있다.
- 대표 이미지는 MVP에서 사진 보관함에서 선택해 추가한다. 이미지 URL 입력이나 웹 이미지 검색은 MVP 이후 범위다.

## 구매 결정, 아카이브, 삭제

- 사용자는 카테고리 목록에서 여러 후보를 선택하고, 그중 구매한 상품 하나를 지정할 수 있다.
- 구매 결정 시 선택한 모든 후보를 한 번에 아카이브한다. 아카이브에는 구매한 상품과 함께 비교했던 후보를 남긴다.
- 아카이브 묶음의 기본 제목은 구매한 상품의 제품명이며, 사용자는 이 제목을 수정할 수 있다.
- 기본 카테고리 목록에는 아카이브된 항목을 표시하지 않는다. 아카이브에서 과거 구매 결정과 비교 후보를 다시 볼 수 있다.
- 항목 삭제는 아카이브와 별도로 제공한다.

## 품질·보안 요구사항

- URL fetch는 SSRF 방어를 적용한다: HTTP(S)만 허용, private/loopback/link-local IP 차단, redirect 목적지 재검증, timeout 및 response 크기 제한.
- 실패한 작업은 원인을 기록한다. 사용자 재시도 UX는 MVP 이후 범위다.
- Worker는 같은 작업이 중복 전달되어도 결과가 망가지지 않게 idempotent해야 한다.
- API와 앱은 네트워크 단절 중에도 저장 요청의 실패 상태를 사용자에게 명확히 보여야 한다.

## 아직 결정되지 않은 사항

- PostgreSQL 제공자, Auth, Queue, Hosting의 구체적 공급자
- taxonomy의 실제 명칭과 leaf category 수
- 목적 확인 대상의 일괄 처리 범위와 노출 시점
- `UNCONFIRMED` 항목을 나중에 다시 확인하고 확정하는 상세 동작
- JS-rendered 사이트에 Playwright를 언제·어디까지 적용할지
- 처리 완료 알림을 polling, realtime, push 중 무엇으로 제공할지
