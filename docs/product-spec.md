# 제품 기능 및 스펙

> 상태: **제안** · 최종 갱신: 2026-08-29

## 제품 목적

Safari, Chrome 등에서 발견한 상품 URL을 OS 공유 기능으로 빠르게 저장하고, 서버가 상품 정보를 보강해 개인 위시리스트로 보여주는 native 모바일 앱이다.

## 핵심 사용자 흐름

1. 사용자가 브라우저 또는 지원 앱에서 상품 URL을 공유한다.
2. iOS Share Extension 또는 Android Share Receiver가 URL을 수신한다.
3. 앱은 URL을 우선 저장 요청하고, 항목을 `PROCESSING` 상태로 목록에 즉시 표시한다.
4. 서버 Worker가 URL을 분석해 상품 메타데이터와 AI 카테고리를 채운다.
5. 항목은 추출 결과에 따라 완료, 일부 정보 누락 또는 실패 상태가 된다. 어느 상태에서나 원본 링크를 웹뷰로 열 수 있다.
6. AI는 taxonomy 안에서 카테고리를 자동 분류한다. 사용자는 필요할 때만 카테고리를 변경하며, 사용자 선택은 AI 결과보다 우선한다.

## MVP 범위

### 포함

- 로그인한 사용자별 위시리스트

- 비동기 상품 메타데이터 추출
  - 제목, 대표 이미지, merchant/domain, 가능한 경우 가격과 통화
  - 가능한 경우 brand와 구조화 metadata
- 미리 정의된 taxonomy에서의 AI 카테고리 분류
- 카테고리 수동 수정
- 사용자가 만든 목적별 비교 묶음과, 기존 목적에 대한 AI 항목 연결
- 새로 저장한 항목의 카테고리·목적 연결 검토 및 수정
- 목적 탭에서의 목적 생성·목적별 상품 선택
- 추출 실패·누락 시 제품명과 대표 이미지를 직접 입력·수정
- 사진 보관함에서 대표 이미지 선택
- 처리 상태와 카테고리별 기본 목록 조회
- 항목 삭제
- 사용자가 선택한 비교 후보 중 구매한 상품을 지정하고, 해당 후보를 일괄 아카이브
- 아카이브 묶음 제목 수정

- 가격 변동 알림
- 품절/재입고 감지
- 추출 작업 재시도
- 전문 검색, 유사 상품, 개인화 추천
- 자체 ML 모델 학습·호스팅, GPU 운영

## Taxonomy 방향 (확정된 원칙 + 남은 세부 설계)

- 분류 체계는 **상위 카테고리와 세부 상품 유형(leaf category)**으로 구성한다. 사용자는 상위 카테고리로 탐색할 수 있고, 실제 상품 분류와 비교의 기준은 세부 상품 유형으로 삼는다.
- 첫 출시 공용 taxonomy는 [상위 카테고리 11개와 세부 유형 87개](product-taxonomy-draft.md)로 정한다. 이후 새 공용 카테고리·세부 유형은 실제 사용자 로그의 미분류, 반복 커스텀 카테고리, 반복 수동 수정 패턴을 검토해 도입한다.
- 현재 taxonomy에 없는 상품은, 사용자가 자신의 위시리스트 안에서 쓸 **사용자 전용 세부 카테고리**로 추가할 수 있다. 이것은 모든 사용자에게 노출되는 공용 taxonomy 변경과 구분한다.
- 사용자 전용 카테고리는 반드시 선택한 상위 카테고리 아래의 세부 카테고리여야 한다. 생성할 때는 이름을 입력하고, 필요하면 짧은 설명과 포함 예시를 덧붙인다.
- 사용자 전용 카테고리는 사용자가 입력한 그대로 개인 목록에 저장하며, 카테고리 적합성에 대한 수정·재입력 절차를 요구하지 않는다. 서버는 과도한 생성과 안전하지 않은 텍스트를 제한하고, AI 입력에 부적합하거나 안전하지 않은 카테고리는 내부적으로 AI 분류 후보에서만 제외할 수 있다.
- 카테고리는 상품이 **무엇인지**를 나타내는 계층형 분류이고, 목적은 사용자가 상품을 **왜 비교하는지**를 나타내는 사용자 전용 비교 맥락이다. 예를 들어 `디지털 > 헤드폰`은 카테고리이고, `출퇴근용 노이즈 캔슬링 헤드폰`은 목적이다.
- 사용자가 먼저 만든 목적에 대해 AI가 새 상품의 연결 가능성을 판단한다. AI는 사용자 의도를 알 수 없는 새 목적을 자동 생성하지 않고, 기존 목적과의 연결 확신이 낮으면 `목적 미지정`으로 남긴다.
- 저장 흐름에서 별도 질문이나 확인을 강제하지 않는다. 새 항목의 처리 후에는 기본 진입 화면에서 카테고리와 목적의 자동 연결 결과를 확인·수정할 수 있게 한다.
- AI의 목적 연결은 자동 추천 문구나 자동 구매 결정을 만들지 않는다. 사용자는 연결을 유지·변경·해제할 수 있다.
- 사용자는 목적 탭의 `목적 추가`에서 목적을 만든다. 목적 이름은 필수이고, 설명과 아이콘은 선택이다. 상품 목록에서 포함할 항목을 선택할 수 있으며, 새 목적은 항목 없이도 만들 수 있다.
- 외부 링크로 새 항목이 추가된 뒤 `분류·목적 확인`에서 사용자는 기존 목적을 선택하거나 새 목적을 만들어 바로 연결할 수 있다.
- 상품 정보 편집 화면에서도 목적을 변경하거나 해제할 수 있다.

### 초기 세부 유형 경계

- `헤드폰`에는 게이밍 헤드셋을 포함한다.
- `의자`에는 사무용·게이밍·식탁 의자를 함께 둔다.
- 뷰티에서는 `스킨케어`와 `메이크업`을 분리한다.
- `키보드`는 세부 유형 하나로 둔다. 기계식·저소음 등은 별도 세부 유형으로 나누지 않는다.

## 기능 규칙

- URL 저장 요청은 상품 분석이 끝날 때까지 기다리지 않는다.
- 같은 canonical URL은 하나의 공용 `Product`를 가리킬 수 있고, 각 사용자의 저장 행위는 별도 `WishlistItem`이다.
- 사용자가 공유한 원본 URL은 tracking parameter 등을 포함할 수 있으므로 공용 Product 데이터로 무분별하게 공유하지 않는다.
- AI는 공용 taxonomy에는 새 카테고리를 만들지 않는다. 사용자 전용 세부 카테고리는 해당 사용자의 분류 후보로 함께 제공할 수 있다. 서버의 안전성 판단으로 후보에서 제외된 카테고리도 사용자의 개인 목록에는 유지된다.
- AI 분류 결과는 저장 흐름에서 별도의 사용자 확인을 요구하지 않는다. 사용자는 목록 또는 상품 편집 화면에서 언제든 카테고리를 변경할 수 있다.
- 카테고리는 구매 후보를 비교하는 목록의 기본 그룹 기준이며, 항목의 저장 시점도 함께 보관한다.
- 카테고리 안의 활성 항목은 최근 저장순으로 표시한다. MVP에서는 다른 정렬 기준을 제공하지 않는다.
- 추출된 가격은 비교를 위한 참고 정보이며, 원래 금액·통화와 마지막 확인 시점을 함께 표시한다. 가격을 실시간 정보로 보장하지 않는다.
- 가격의 통화는 ISO 4217 통화 코드와 함께 보관하며, 항목마다 원래 통화로 표시한다. 서로 다른 통화의 환율 환산은 MVP 범위에 포함하지 않는다.
- MVP의 기본 분류 체계는 상품 taxonomy이며, 사용자가 만든 목적별 비교 묶음은 taxonomy와 별개로 둔다. AI는 최근 활성 위시리스트와 사용자가 만든 목적의 문맥을 참고해 새 항목을 기존 목적에 연결할 수 있다.
- MVP에서 각 활성 항목은 하나의 카테고리와 최대 하나의 목적에 연결한다. 목적 연결을 원하지 않거나 확신이 낮은 항목은 `목적 미지정`으로 둘 수 있다.
- 빈 목적은 자동으로 삭제하지 않는다. 사용자가 직접 삭제할 때까지 유지한다.
- 처리 상태와 무관하게 사용자가 공유한 원본 링크를 웹뷰로 열 수 있다.
- 추출이 실패했거나 제품명·대표 이미지가 누락된 항목은 사용자가 해당 정보를 직접 추가하거나 수정할 수 있다.
- deterministic parser 결과가 충분하면 AI는 추출 대체 수단이 아니라 분류·정규화 보조 수단으로 쓴다.

## 목록과 상태 표현

- 앱의 기본 진입 화면은 카테고리별 구매 후보를 살펴보기 전, 사용자의 조치가 필요한 항목을 한눈에 확인하는 요약 화면이다.
- 진입 화면 상단에는 `분류 중`과 `정보 보완 필요` 영역을 둔다. 이 영역은 각각 처리 중인 항목과 카테고리·제품 정보 보완이 필요한 항목을 보여준다.
- 새로 처리된 항목 중 카테고리 또는 목적의 자동 연결 결과를 아직 확인하지 않은 항목은 `분류·목적 확인` 영역에 표시한다. 사용자는 결과를 유지하거나 한 화면에서 수정·해제할 수 있다.
- `분류·목적 확인` 카드에서 오른쪽 스와이프는 현재 카테고리·목적 연결을 `확정`하고, 왼쪽 스와이프는 `보류`한다. 보류한 항목은 이 영역에 다시 자동 노출하지 않되, 목록 카드에서 미확정 상태임을 표시한다. 스와이프를 사용할 수 없는 경우에는 같은 동작의 명시적 버튼을 제공한다.
- `PROCESSING` 항목은 원본 링크, 로딩 인디케이터, `상품 정보 추출 중` 문구를 표시한다.
- 정보가 완성된 항목은 해당 카테고리의 일반 상품 카드로 표시한다. 내부의 `READY` 상태를 별도 화면 상태로 강조하지 않는다.
- `PARTIAL` 항목은 분류된 카테고리에 표시할 수 있으며, 누락된 제품명·대표 이미지를 추가하는 행동을 제공한다.
- `FAILED` 또는 카테고리를 정할 수 없는 항목은 `정보 보완 필요` 영역에 표시한다. 실패 사실을 알리고, 원본 링크 열기와 제품명·대표 이미지·카테고리 직접 입력을 제공한다.
- 사용자가 카테고리를 정하면 해당 항목은 즉시 그 카테고리의 비교 목록에 표시된다.

## 상품 정보 편집

- 직접 보완과 추출 완료 후의 수정은 동일한 상품 정보 편집 화면에서 수행한다.
- 편집 화면에서는 제품명, 대표 이미지, 카테고리, 목적을 한 번에 입력하거나 수정할 수 있으며, 원본 링크를 열 수 있다.
- 대표 이미지는 MVP에서 사진 보관함에서 선택해 추가한다. 이미지 URL 입력이나 웹 이미지 검색은 MVP 이후 범위다.

## 구매 결정, 아카이브, 삭제

- 사용자는 목적에 포함된 후보 중 구매한 상품 하나를 지정할 수 있다.
- 구매 결정 시 해당 목적과 그 목적에 포함된 모든 후보를 한 번에 아카이브한다. 아카이브에는 구매한 상품과 함께 비교했던 후보를 남긴다.
- 아카이브 묶음의 기본 제목은 구매한 상품의 제품명이며, 사용자는 이 제목을 수정할 수 있다.
- 기본 카테고리 목록에는 아카이브된 항목을 표시하지 않는다. 아카이브에서 과거 구매 결정과 비교 후보를 다시 볼 수 있다.
- 아카이브된 후보는 복원할 수 있다. 복원된 항목은 활성 목록으로 돌아오며 새 목적에 다시 연결할 수 있고, 기존 아카이브의 구매 결정·후보 기록은 바뀌지 않는다.
- 항목 삭제는 아카이브와 별도로 제공한다.

## 품질·보안 요구사항

- URL fetch는 SSRF 방어를 적용한다: HTTP(S)만 허용, private/loopback/link-local IP 차단, redirect 목적지 재검증, timeout 및 response 크기 제한.
- 실패한 작업은 원인을 기록한다. 사용자 재시도 UX는 MVP 이후 범위다.
- Worker는 같은 작업이 중복 전달되어도 결과가 망가지지 않게 idempotent해야 한다.
- API와 앱은 네트워크 단절 중에도 저장 요청의 실패 상태를 사용자에게 명확히 보여야 한다.

## 아직 결정되지 않은 사항

- PostgreSQL 제공자, Auth, Queue, Hosting의 구체적 공급자
- 사용자 전용 카테고리의 이름 변경·삭제 정책과, 서버의 안전성 제한·AI 후보 제외의 구체적 기준
- 비어 있지 않은 목적을 사용자가 삭제할 때 포함 항목을 어떻게 처리할지
